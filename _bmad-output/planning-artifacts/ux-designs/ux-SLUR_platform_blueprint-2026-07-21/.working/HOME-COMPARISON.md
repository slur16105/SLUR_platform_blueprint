## 0. 참고 대상에 대해 — 먼저 밝힐 것

지시대로 `https://wch.eqlstore.com/main`의 **정보 구조·여백·에디토리얼 큐레이션 문법만** 참고 대상으로 삼았고, 로고·카피·이미지·색·브랜드 식별 요소는 어느 것도 옮기지 않았다. 세 시안의 모든 색·활자·간격은 SLUR 확정 스파인(`DESIGN.md`)에서만 나온다.

**다만 한 가지를 정직하게 적는다.** 그 페이지는 클라이언트 렌더링이라 자동 열람 도구로는 본문이 잡히지 않았고, **회수된 것은 푸터 영역뿐**이다. 확인된 구조는 다음 정도다.

- 상단: 로고 · 검색 · 회원가입/로그인 · 브랜드 · 장바구니
- 푸터: 회사정보 → 연락처·사업자정보 → 고지사항 → 저작권 → 고객센터 링크군 → 소셜 → 회사소개 링크군
- 타이포 위계는 제목 > 본문 > 링크 라벨 3단, 섹션 간격은 균일

따라서 히어로·기획전 섹션의 실제 구성은 **관찰이 아니라 에디토리얼 커머스의 일반 문법으로 대체해 설계했다.** 그 문법에서 가져온 것은 넷이다 — ① 첫 화면을 상품 격자가 아니라 편집 지면으로 연다 ② 큐레이션 섹션은 `라벨 → 표제 → 문장 → 품목 묶음 → 더 보기` 한 벌로 반복한다 ③ 섹션 사이 여백을 상품 사이 여백보다 확실히 크게 둔다 ④ 전체 상품 격자는 편집 지면 **뒤에** 놓는다.

> **Dan 확인 필요 (Q0)** — 실제 EQL 화면에서 꼭 가져오고 싶은 구체적 구조가 따로 있다면, 스크린샷을 `imports/`에 넣어 주면 그것을 정본 삼아 다시 맞춘다. 없으면 위 4개 문법으로 확정한다.

## 1. 세 시안이 실제로 나누는 축

세 안의 차이는 취향이 아니라 **"큐레이션 자리를 무엇이 채우는가"** 한 가지다. 그리고 그 답이 곧 구현 비용이다.

| | A · 서문 | B · 초대 | C · 편성 |
|---|---|---|---|
| 히어로 | 활자와 여백만 (이미지 0) | 한 팀의 대표 품목 1점 | 운영자가 편성한 대형 지면 |
| 큐레이션 자리를 채우는 것 | **카테고리** | **브랜드(판매자)** | **운영자가 고른 묶음** |
| 편집자의 목소리가 놓이는 곳 | 히어로 서문 한 곳 | 히어로 한 곳 (+ 팀 소개는 선택) | 히어로 + 슬롯마다 |
| 새 DB 필드·테이블 | **0** | 0 또는 1 (아래 B-2) | **새 테이블 1 + 이미지** |
| 새 공개 API | 0 (기존 조회 재사용) | **1** (브랜드별 조회) | **1** (편성 조회) |
| 새 관리자 화면 | 0 | 0 | **1 (편성 화면)** |
| PRD 화면 목록 | 안 벗어남 | 안 벗어남 | **벗어남 — 승인 필요** |
| 운영자가 매주 해야 하는 일 | 없음 | 없음 (자동 정렬) | **지면 편성** |
| 첫 화면의 시각적 임팩트 | 낮음 | 중간 | 높음 |
| 판매자 5~10팀 규모 적합도 | 높음 | **가장 높음** | 낮음 (채울 내용이 부족) |

## 2. 시안 A · 서문 (Preface)

**구조** — 헤더 → 히어로(눈썹 `큐레이션` + 25/40px 표제 2줄 + 서문 3줄 + hairline + `초대한 팀 4 · 진열 중인 품목 8`) → 8px 접기 띠 → 카테고리 칩 → 큐레이션 섹션 2개(카테고리별 가로 스트립) → 접기 띠 → 전체 상품 리듬 그리드 + `더 보기` → 푸터.

히어로에 이미지가 없다. 지금 `/`의 `큐레이션 / 골라온 것들을 천천히 봅니다`를 그대로 살려 전면 서문으로 키운 형태이며, 데스크톱에서 상하 84/64px 여백을 준다. 큐레이션 섹션은 **소개 문장을 두지 않는다** — 라벨(`리빙`)과 개수만 둔다. 편집자의 목소리를 히어로 한 곳에만 두는 것이 이 안의 논지다.

**장점**
- 구현 비용이 사실상 프론트엔드뿐. 새 데이터·관리자 화면 0건이라 **오픈 게이트를 늦추지 않는다.**
- 상품이 8개든 80개든 화면이 비어 보이지 않는다. 초기 규모에 가장 안전하다.
- 확정 톤 B(매거진)의 "색으로 소리치지 않는다"와 가장 잘 맞는다. 사진 없는 첫 화면은 편집숍에서 드물지 않다.

**단점**
- 첫 화면에 사진이 없어 **모바일 첫 스크롤 전까지 상품이 하나도 안 보인다.** 구매 전환에는 불리하다.
- 카테고리 = 큐레이션이라 "운영자가 직접 골랐다"는 서사가 문장으로만 남고 구조로는 증명되지 않는다.
- 카테고리가 1~2개뿐인 지금은 섹션 반복의 리듬이 약하다.

**SLUR 적합성** — 완주 우선이라는 1차 목표에 가장 정직한 안. "기능 추가 판단 기준은 완주에 기여하는가"를 그대로 통과한다. 반면 편집숍의 얼굴로서는 가장 조용하다.

**구현 시 주의** — 카테고리별 스트립은 기존 `/api/products?category=`를 카테고리 수만큼 부르게 된다. 카테고리가 늘면 홈 진입에 N번 왕복이 생기므로, 채택 시 **홈 전용 묶음 응답 1개로 합치는 것**을 권한다(새 테이블은 여전히 0건).

## 3. 시안 B · 초대 (Invitation)

**구조** — 헤더 → 히어로(≥768 좌우 2단: 이미지 50% / 눈썹 `이번에 초대한 팀` + 브랜드명 15px·자간 .18em + 상품명 + 소개 문장 + 가격 + 버튼 2개, <768 이미지 위·글 아래) → 접기 띠 → 카테고리 칩 → **팀별 섹션 3개**(브랜드명 16px/800/.17em + hairline + 그 팀 품목 3점 3열) → 접기 띠 → 전체 상품 리듬 그리드 → 푸터.

팀별 섹션의 카드에는 **브랜드 라벨을 다시 붙이지 않는다.** 섹션 머리가 이미 브랜드이기 때문이다. 전체 상품 그리드에서는 붙는다 — 브랜드가 섞이는 곳에서만 라벨이 일을 한다.

**장점**
- **SLUR의 정체성이 IA 그 자체가 된다.** "운영자가 판매자를 직접 선별·초청한다"가 홈의 구조로 보인다.
- DESIGN.md가 이 시스템의 지문이라고 못 박은 "브랜드명이 상품명보다 먼저 읽힌다"를 홈에서 증명한다. 세 안 중 스파인과의 정합성이 가장 높다.
- 판매자 5~10팀 규모에 가장 잘 맞는다. 팀이 늘수록 홈이 저절로 길어지고, 줄어도 무너지지 않는다.
- 운영자가 매주 편성할 필요가 없다. 정렬 규칙 하나만 정하면 자동으로 돈다.

**단점**
- 판매자 수가 3팀 미만이면 홈이 짧고 단조롭다.
- **팀 노출 순서를 정해야 한다.** 승인일 역순이 자연스러운데 공개 API가 승인 시각을 내지 않는다 — 정렬 기준을 정하고 필드를 노출해야 한다.
- 히어로의 소개 문장(`같은 나무를 20년…`)은 **지금 DB에 없는 값**이다. 아래 B-2 참조.
- 한 팀이 상품 1개만 가진 경우 3열 섹션에 빈자리가 생긴다 — 2개 이하면 섹션을 접는 규칙이 필요하다.

**구현 비용 두 갈래**
- **B-1 (필드 추가 없음)** — 히어로에서 소개 문장을 빼고 이미지·브랜드·상품명·가격만 둔다. 새 DB 필드 0건, 브랜드별 공개 조회 수단 1건만 추가. 대신 히어로가 "큰 상품 카드"에 가까워져 B의 매력이 절반쯤 깎인다.
- **B-2 (권장)** — 판매자에 **브랜드 한 줄 소개** 필드 1개를 추가한다(판매자 입점 정보 또는 운영자 입력). 히어로와 팀 섹션이 함께 살아난다. ERD 변경이므로 **Dan 승인 후 진행**한다.

## 4. 시안 C · 편성 (Feature)

**구조** — 헤더 → 히어로(전면 이미지 320/480px + 그 아래 `이번 지면` + `NO. 07 · 2026.07` + 25/38px 표제 + 서문 + `지면 보기`) → 접기 띠 → **편성 슬롯 1**(≥768 비대칭 5:7 — 좌측 편집 문장, 우측 고른 품목 2점) → 접기 띠 → **편성 슬롯 2**(`함께 보기` 가로 스트립) → 접기 띠 → 카테고리 칩 → 전체 상품 그리드 → 푸터.

글자를 이미지 위에 얹지 않는다 — DESIGN.md가 오버레이 그라디언트를 금지하므로 표제는 항상 이미지 **아래** 블록에 놓인다. 이것이 이 톤에서 대형 비주얼을 쓰는 유일한 방법이다.

**장점**
- 에디토리얼 밀도가 가장 높다. "지면을 흉내 낸다"는 DESIGN.md의 선언을 가장 멀리 밀고 간 형태다.
- 상품 수가 적어도 화면이 빈약해 보이지 않는다 — 편집이 부피를 만든다.
- 확장성이 가장 좋다. 지면 번호(NO. 07)를 쌓으면 시간이 지날수록 아카이브가 자산이 된다.

**단점 — 이 안의 진짜 문제**
- **PRD 화면 목록 밖이다.** 새 테이블(지면: 제목·문장·이미지·품목 묶음·노출 순서·기간) + 관리자 편성 화면 1개 + 이미지 업로드 경로가 필요하다. CLAUDE.md의 "완주에 기여하는가" 기준을 정면으로 시험한다.
- **운영 부담이 상시로 생긴다.** 아무도 편성하지 않으면 홈이 비거나 낡은 지면이 계속 걸린다 — 편성이 비었을 때의 대체 화면(A로 폴백)까지 설계해야 한다.
- 판매자 4팀·상품 8개 규모에서 "이번 지면"을 매달 새로 만들 소재가 실제로 나오는지 검증되지 않았다.
- 오픈 게이트(PG·사업자 실정보·법률 검토)가 남은 지금 새 에픽을 하나 더 얹는다.

**SLUR 적합성** — 도달점으로는 가장 옳고, **지금 시점으로는 가장 이르다.** 채택한다면 v1 오픈 이후의 별도 에픽으로 미루고, 오픈은 A 또는 B로 하는 것이 안전하다.
