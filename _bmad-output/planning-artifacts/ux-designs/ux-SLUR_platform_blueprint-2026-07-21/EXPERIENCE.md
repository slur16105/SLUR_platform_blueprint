# SLUR 구매자 웹 — 경험 스파인

동작 계약. 시각 계약(색·활자·간격·컴포넌트 생김새)은 [DESIGN.md](./DESIGN.md)에 있고, 여기서는 `{colors.accent}` 같은 이름으로 참조한다.

## Foundation

**모바일 퍼스트 반응형 웹(PWA).** 구매자의 접점은 모바일 브라우저다. 설치형 앱이 아니라 링크로 열리는 웹이며, PWA로 홈 화면에 얹을 수 있다. (2026-07-21 코스 코렉션 — 구매자 표면을 Flutter 네이티브 앱에서 반응형 웹으로 전환 확정.)

**판매자·관리자와 같은 Next.js 앱이다.** 코드베이스는 하나이고 Role로 갈린다. 데이터·권한·상태 전이는 전부 FastAPI가 소유하며, 이 화면들은 FastAPI API만 호출한다. Supabase Auth·RLS는 쓰지 않는다.

**기존 슬러 시스템 CSS를 상속한다** (`apps/web/app/styles/slur` — 토큰 7·컴포넌트 7). 지금까지 판매자·관리자 화면에만 닿아 있던 시스템을 구매자 화면을 위해 모바일 퍼스트로 확장한다. 글꼴 스택·라운드 스케일·브레이크포인트는 그대로 물려받고, **색은 갈린다** — 구매자는 흙빛, 판매자·관리자는 파랑. 자세한 것은 DESIGN.md.

`[ASSUMPTION]` PWA의 범위(manifest 항목, 오프라인 캐시 대상, 설치 유도 시점)는 아직 결정된 바 없다. v1은 "브라우저에서 정상 동작하는 반응형 웹 + 최소 manifest"까지로 본다.

`[ASSUMPTION]` 다크 모드는 v1에 없다. 슬러 시스템은 `data-theme="dark"`를 지원하지만 구매자 팔레트는 라이트 한 벌만 정의되어 있다.

## Information Architecture

전 9화면 + 내 정보. 최상위 4개는 탭바로, 나머지는 뒤로가기 헤더로 닿는다.

| # | 화면 | 도달 경로 | 헤더 | 탭바 | 하단 고정 CTA |
|---|---|---|---|---|---|
| 1 | 상품목록 (홈) | 앱 진입 · `홈` 탭 | 로고 + 장바구니 | 있음 (`홈`) | 없음 |
| 2 | 상품상세 | 상품 카드 탭 | 뒤로가기 + 장바구니 | 없음 | `장바구니 담기` / `바로 구매` |
| 3 | 장바구니 | `장바구니` 탭 · 상단바 아이콘 | 제목 (좌측) | **있음** (2단 예외) | `주문하기 (N건)` |
| 4 | 로그인 | 미로그인 상태에서 보호된 동작 시도 | 로고 중앙 | 없음 | 없음 |
| 5 | 회원가입 | 로그인 하단 링크 | 뒤로가기 + 제목 | 없음 | 없음 |
| 6 | 주문서 | 장바구니 CTA · 상세 `바로 구매` | 뒤로가기 + 제목 | 없음 | `121,000원 · 주문하기` |
| 7 | 주문완료 | 주문서 CTA | 로고 중앙 | 없음 | 없음 (본문 버튼 2개) |
| 8 | 주문내역 | `주문내역` 탭 · 내 정보 메뉴 · 주문완료 | 제목 | 있음 (`주문내역`) | 없음 |
| 9 | 주문상세 | 주문내역 행 탭 · 주문완료 `주문 상세 보기` | 뒤로가기 + 제목 | 없음 | 없음 |
| 10 | 내 정보 | `내 정보` 탭 | 제목 | 있음 (`내 정보`) | 없음 |

**탭 4개**: `홈` · `장바구니`(개수 배지) · `주문내역` · `내 정보`.

**배치 규칙 세 줄.**
1. 탭바는 최상위 4화면에만 둔다. 상세·플로우 화면은 뒤로가기 헤더로 돌아간다.
2. 하단 고정 CTA가 있는 화면에는 탭바를 두지 않는다 — 두 바가 겹치면 112px을 먹는다.
3. **장바구니만 예외**로 합계 CTA + 탭바 2단을 허용한다. 최상위이면서 결제로 넘어가는 지점이기 때문이다.
4. **최상위 화면의 헤더 제목은 좌측 정렬로 통일한다** (장바구니·주문내역·내 정보). 로고 중앙 헤더는 로그인·주문완료 두 화면에만 쓴다 — 둘 다 탐색 맥락 밖에 있는 화면이다.

**확정 — 로그인 헤더에 뒤로가기를 두지 않는다.** 로그인은 어디서든 밀려 들어오는 화면이라 돌아갈 곳이 하나로 정해지지 않는다. 로고 중앙 헤더를 쓰고 이탈은 브라우저 뒤로 가기에 맡긴다. (목업 `screens-2-account.html` 채택)

**확정 — 장바구니 헤더에 뒤로가기를 두지 않는다.** 최상위 탭 화면이므로 진입 경로와 무관하게 헤더는 같다. 상품상세의 상단바 장바구니 아이콘으로 들어와도 뒤로가기가 아니라 `장바구니` 탭이 활성화된 상태로 전환된다. 목업 `screens-1-browse.html`의 뒤로가기는 이 규칙에 따라 무시한다 — **스파인이 이긴다.**

**확정 — `내 정보` 화면을 둔다** (Slur, 2026-07-21). PRD 구매자 8화면 목록 밖이지만 신규 기능이 아니라 기존 Flutter `service_info_screen.dart`의 웹 대응이며, FR-31(사업자 정보·중개자 고지)·FR-33(약관)이 놓일 자리다. 여기에 회원정보 수정·배송지 관리·찜 같은 v1 밖 기능을 붙이지 않는다.

## 라우트와 접근 권한

**확정 (Slur, 2026-07-21)**

| 화면 | 라우트 | 로그인 |
|---|---|---|
| 상품목록 (홈) | `/` | **불필요** |
| 상품상세 | `/products/[id]` | **불필요** |
| 장바구니 | `/cart` | 필요 |
| 주문서 | `/checkout` | 필요 |
| 주문완료 | `/orders/complete` | 필요 |
| 주문내역 | `/orders` | 필요 |
| 주문상세 | `/orders/[id]` | 필요 |
| 내 정보 | `/me` | 필요 |
| 로그인 · 회원가입 | `/login` · `/signup` | — |

**`/`는 구매자 상품목록이다.** 지금 웹의 `/`는 로그인 유도 랜딩인데, 이 자리를 구매자 홈에 내준다. 판매자·관리자도 `/`로 들어와 상품을 보고, 자기 화면(`/seller`·`/admin`)으로는 헤더 또는 로그인 후 안내를 통해 이동한다 — 한 계정이 여러 역할을 가질 수 있으므로(FR-3) 역할별로 진입점을 쪼개지 않는다.

**비로그인은 상품목록·상품상세까지 볼 수 있다.** 큐레이션 편집숍에서 물건을 먼저 보여주는 것이 로그인을 먼저 요구하는 것보다 중요하다. 장바구니에 담는 순간부터 로그인이 필요하다.

- 비로그인 상태로 `장바구니 담기`를 누르면 → `/login`으로 보내고, 로그인 성공 후 **원래 상품상세로 돌아와 담기를 이어간다**. 담으려던 조합을 잃어버리면 안 된다.
- 비로그인 상태에서 탭바의 `장바구니`·`주문내역`·`내 정보`를 누르면 → `/login`.
- `[ASSUMPTION]` 비로그인 장바구니를 브라우저에 임시 보관할지는 정하지 않았다. v1은 **보관하지 않는 쪽**을 기본으로 둔다 — 서버 장바구니와 병합하는 규칙이 필요해지고, 그 복잡도가 완주에 기여하지 않는다.

**모달은 쓰지 않는다.** 우편번호 검색만 예외로 오버레이가 필요하다 (`[ASSUMPTION]` 검색 제공자 미정 — 아키텍처 단계 결정 사항).

→ 구성 참조: [탐색 3화면](./.working/screens-1-browse.html) · [계정 3화면](./.working/screens-2-account.html) · [주문 진행 2화면](./.working/screens-3-checkout.html) · [주문 조회 2화면](./.working/screens-4-orders.html).
**스파인이 목업과 충돌하면 스파인이 이긴다.**

## Voice and Tone

문구 규칙. 브랜드의 미감은 DESIGN.md에 있다.

조용하고 담백한 존댓말. 감탄사·마케팅 과장·이모지 없음. 화면은 구매자를 재촉하지 않고, 사실과 다음 할 일만 말한다.

| Do | Don't |
|---|---|
| `주문이 접수되었습니다` | `주문 완료! 🎉` |
| `담은 뒤 품절된 상품입니다. 주문에서 제외됩니다.` | `일부 상품을 구매할 수 없습니다 ⚠` |
| `이메일 또는 비밀번호가 올바르지 않습니다.` | `로그인 실패 (401)` |
| `입금 확인 후 배송이 시작됩니다. 주문 후 3일 안에 입금하지 않으면 자동 취소됩니다.` | `지금 입금하지 않으면 주문이 사라져요!` |
| `배송준비 전까지 판매자 묶음 단위로 취소할 수 있습니다.` | `취소 불가 상품이 포함되어 있습니다` |
| 버튼은 짧은 동사형 — `장바구니 담기` `주문하기` `삭제` `주문 취소` | `지금 바로 구매하기` `장바구니에 담아두기` |
| 금액 `121,000원` · 날짜 `2026.07.21` 또는 `2026년 7월 21일` | `₩121,000` `12.1만원` `7/21` |
| 판매자를 부를 때는 브랜드명 — `토림도예`, `온실` | `판매자 A`, `업체명` |

법적 고지 문구는 **글자 그대로** 쓴다. 요약·의역하지 않는다:
`SLUR는 통신판매중개자이며 통신판매의 당사자가 아닙니다. 상품 정보와 거래에 관한 책임은 판매자에게 있습니다.`

## Component Patterns

동작 규칙. 생김새는 `DESIGN.md.Components`에 있다.

| 컴포넌트 | 쓰는 곳 | 동작 규칙 |
|---|---|---|
| 하단 탭바 | 최상위 4화면 | 탭 전환 시 각 탭의 스크롤 위치를 유지한다. 같은 탭 재탭은 최상단 복귀. 장바구니 배지는 **담긴 항목 수 전체**(구매 불가 포함)를 센다 — CTA의 `(N건)`은 주문 가능 항목만 세므로 두 숫자는 다를 수 있다. |
| 카테고리 칩 | 상품목록 | 가로 스크롤, 단일 선택, 기본 `전체`. 선택은 즉시 목록을 갈아끼운다. 카테고리는 운영자가 관리하므로 이름을 하드코딩하지 않는다 (FR-34). |
| 상품 카드 | 상품목록 | 탭 → 상품상세. 품절 카드도 탭할 수 있다 — 상세에서 어떤 조합이 남았는지 볼 수 있어야 하기 때문. |
| 옵션 축 칩 | 상품상세 | 축(색상·용량)마다 단일 선택. 한 축을 고르면 다른 축의 칩 상태가 즉시 갱신된다. 두 축이 다 정해지면 아래 **선택 결과 한 줄**에 조합 상태가 나온다. 조합 목록을 따로 나열하지 않는다. |
| 판매자 묶음 | 장바구니 · 주문서 · 주문상세 | 장바구니에서는 체크박스·수량·삭제를 갖고, 주문서에서는 읽기 전용, 주문상세에서는 **각자의 상태·배송비·취소 버튼**을 갖는다. 주문 전체에 걸리는 상태나 전체 취소 버튼은 두지 않는다 (FR-15·18). |
| 수량 스테퍼 | 장바구니 | `−` `n` `+`. 1에서 `−`는 비활성(삭제와 구분한다). 변경은 즉시 합계에 반영. 구매 불가 항목의 스테퍼는 비활성. |
| 금액 요약 | 장바구니 · 주문서 · 주문상세 | 상품 금액 · 배송비 · 도서산간 추가 · 합계 순서 고정. 도서산간 추가는 0원이어도 **줄을 지우지 않는다** — 배송지에 따라 늘어날 자리가 있다는 것을 미리 보여준다. |
| 입금 안내 상자 | 주문완료 · 주문상세(입금대기) | 금액·계좌·예금주·기한·입금자명 안내를 한 덩어리로. 입금대기가 아닌 주문의 상세에서는 **사라진다**. |
| 하단 고정 CTA | 상품상세 · 주문서 · 장바구니 | 스크롤과 무관하게 붙어 있다. 금액을 표시하는 CTA는 합계와 항상 같은 값. |
| 상태 라벨 | 주문내역 · 주문상세 | 면 없는 글자. 색 + 텍스트를 항상 함께 쓴다 (색만으로 상태를 전달하지 않는다). |
| 법적 고지 | 상품상세 · 주문서 · 내 정보 | 접히지 않는 고정 텍스트. 판매자 정보만 접이식이되 **기본 펼침**. 아래 "법적 고지 배치 규칙" 참조. |

## State Patterns

이 제품의 핵심이 여기 있다. **재고와 상태는 구매자가 보는 사이에 움직인다** — 담아둔 물건이 품절되고, 판매자 두 곳의 배송이 따로 간다. 이 화면들의 일은 그 어긋남을 정직하게 보여주는 것이다.

### 재고 · 판매 상태

| 상태 | 화면 | 처리 |
|---|---|---|
| **상품 품절** (FR-10, 카드 확장) | 상품목록 | **숨기지 않는다.** 사진 채도를 낮추고 좌상단에 `품절` 태그, 이름·가격을 `{colors.ink-muted}`로 내리고 가격에 취소선. 탭하면 상세로 들어간다. `[ASSUMPTION]` FR-10은 옵션 조합에 대한 규칙이며 상품 카드로의 확장은 아직 미확정 — Slur 확인 필요. |
| **옵션 조합 품절** (FR-9·10) | 상품상세 | 축을 고르면 **불가능해진 다른 축의 칩이 비활성으로 표기**된다 — 회색 면 + 취소선 + `품절` 서브라벨. 숨기지 않는다. 일부 조합만 품절인 축 값에는 `일부 품절` 서브라벨. |
| **선택 조합 확정** | 상품상세 | 두 축이 정해지면 선택 결과 줄에 `살구 / 240ml` + `구매 가능`. 품절 조합이 선택되면 같은 자리에 `품절`이 나오고 하단 CTA 두 버튼이 모두 비활성. |
| **상품 전체 품절** | 상품상세 | 모든 조합이 품절이면 CTA 비활성 + `현재 구매할 수 있는 옵션이 없습니다.` `[ASSUMPTION]` 목업에 없는 문구. |
| **담은 뒤 품절** (FR-35) | 장바구니 | 묶음을 흐리게(사진 grayscale, 글자 `#a8a29a`, 금액 취소선), 체크박스 해제·잠금, 헤더에 `구매 불가 · 품절` 태그, 하단에 `담은 뒤 품절된 상품입니다. 주문에서 제외됩니다.` **합계와 `주문하기 (N건)`에서 제외된다.** `삭제`는 계속 눌린다. |
| **주문 생성 시 재검증 실패** (FR-35) | 주문서 → 장바구니 | 주문을 만들지 않고 되돌린 뒤, **어떤 항목이 문제인지** 알린다. `[ASSUMPTION]` 목업에 없다 — 장바구니로 되돌리고 해당 묶음을 구매 불가 상태로 갱신하는 방식을 권장. |

### 주문 상태 (FR-18)

`입금대기` → `결제완료` → `배송준비` → `배송중` → `배송완료`, 그리고 `취소`. 6단계이며 **전이는 판매자 묶음마다 독립**이다 (FR-15).

| 상태 | 표기 | 화면에서 일어나는 일 |
|---|---|---|
| **입금대기** | `{colors.accent}` — 액센트가 붙는 유일한 상태 | 입금 안내 상자가 주문상세 최상단에 뜬다. 묶음에 `주문 취소` 노출. 3일 내 미입금은 자동 취소. |
| **결제완료** | `{colors.ink}` | 입금 안내가 사라진다. 취소 계속 가능. |
| **배송준비** | `{colors.ink}` | `[ASSUMPTION]` 취소 경계가 이 상태의 **진입 전**이므로, 배송준비로 넘어간 묶음에는 `주문 취소`가 없고 `배송준비 이후에는 취소할 수 없습니다.`가 대신 앉는다. |
| **배송중** | `{colors.ink}` | 송장 줄이 나타난다 (`CJ대한통운 1234-5678-9012`). 텍스트 표시까지만 — 추적 링크·연동 없음 (FR-21). 취소 버튼 없음. |
| **배송완료** | `{colors.ink-muted}` — 물러난 색 | 아무 액션도 남지 않는다. `구매확정`은 v1 미사용 (FR-20). |
| **취소** | `{colors.ink-muted}` | `[ASSUMPTION]` 목업에 없다. 묶음 헤더에 `취소`, 금액 취소선 권장. |

**주문내역의 대표 상태.** 목록은 주문 1건에 상태 하나를 보여준다 — 묶음별로 갈렸을 때 무엇을 대표로 쓰는지는 `[ASSUMPTION]`이다. 가장 앞선(덜 진행된) 상태를 대표로 삼는 것을 권장한다. 상세로 들어가면 묶음별 진짜 상태가 나온다.

**취소 가능 여부** (FR-18). 취소는 **묶음 단위**이며, 그 묶음이 배송준비에 들어가기 전까지만 가능하다. 주문 전체를 한 번에 취소하는 버튼은 두지 않는다. 화면 하단에 항상 `배송준비 전까지 판매자 묶음 단위로 취소할 수 있습니다.`를 둔다 — 버튼이 있는 묶음과 없는 묶음이 나란히 놓이는 이유를 설명해야 하기 때문이다.

## 법적 고지 배치 규칙 (FR-31·32)

SLUR는 통신판매중개자다. 고지를 푸터에 한 줄 넣는 것으로는 부족하다는 것이 PRD의 판단이며(FR-32), 이 배치는 **디자인 취향이 아니라 규제 요건**이다. 다음 세 자리는 옮기거나 접거나 지울 수 없다.

| 자리 | 무엇을 | 규칙 |
|---|---|---|
| **상품상세** — 하단 CTA 위 | 판매자 신원정보 6항목(상호·대표자·사업자등록번호·통신판매업 신고번호·사업장 주소·연락처) + 중개자 고지 | 접이식 영역이되 **기본 펼침**. 청약(`장바구니 담기`·`바로 구매`) 버튼보다 **위**에 있어야 한다. |
| **주문서** — 하단 고정 CTA 위 | 중개자 고지 | 스크롤 끝이 아니라 `주문하기` 직전. **청약 전에 읽을 수 있어야 한다.** |
| **내 정보** | 플랫폼 사업자 정보 + 중개자 고지 + 이용약관·개인정보처리방침 링크 | 웹 푸터 대응 (FR-31·33). |

**"청약 전"이 이 규칙의 전부다.** 주문 버튼을 누르기 전 같은 스크롤 흐름 안에서 판매자가 누구인지와 SLUR가 당사자가 아님을 볼 수 있어야 한다. 고지를 모달·별도 페이지·"더보기" 뒤로 숨기는 구현은 이 요건을 만족하지 않는다.

플랫폼 사업자 정보는 현재 placeholder이며 화면에 `임시 정보` 태그와 `실사업자 정보는 서비스 오픈 전에 교체됩니다.`를 함께 보여준다. **실정보 교체와 약관 법률 검토는 실서비스 오픈 게이트 항목**이다 (FR-33).

## Responsive & Platform

**2026-07-21 Slur 확정.** 시각 수치(열 수·간격·최대 폭)는 `{DESIGN.md.Layout & Spacing.반응형}`이 소유한다. 여기서는 **동작이 어떻게 달라지는가**만 정한다.

**하나의 문서, 세 개의 폭.** 별도 모바일 사이트를 만들지 않는다. 같은 라우트·같은 HTML이 폭에 따라 다르게 배치될 뿐이며, 서버가 기기를 판별해 분기하지 않는다 (AD-14 — 표면은 하나다).

| 동작 | < 768 | ≥ 768 |
|---|---|---|
| 화면 이동 | 하단 탭바 4개 | 상단 내비. 탭바는 사라지고 같은 4개 항목이 헤더 우측에 놓인다 |
| 현재 위치 표시 | 탭 아이콘 먹색 + 라벨 800 | 내비 항목 먹색 (밑줄 없이 굵기로만) |
| 주 행동 버튼 | 하단 고정 바 | 우측 sticky 요약 칼럼 안. **화면 밖으로 밀려나면 안 된다** |
| 장바구니 진입 | 탭 | 상단 내비 항목 (배지 동일) |
| hover | 없음 | 카드·행·버튼에 허용. 단 hover에만 있는 정보는 두지 않는다 |
| 우편번호 검색 | 전체 화면 오버레이 | 가운데 모달 |

**폭이 바뀌어도 상태는 유지된다.** 창을 넓히거나 기기를 돌려 레이아웃이 재배치될 때 선택한 옵션 조합, 장바구니 체크 상태, 입력 중인 배송지가 초기화되지 않아야 한다.

**2단 화면에서 우측 칼럼이 왼쪽보다 길어지는 경우**(예: 장바구니에 묶음이 하나뿐일 때) sticky를 걸지 않고 자연스럽게 흐르게 둔다 — 짧은 내용 옆에 붙어 다니는 요약은 붕 떠 보인다.

**법적 고지는 폭과 무관하게 같은 자리에 있다.** 상품상세의 판매자 신원정보·중개자 고지는 768 이상에서도 우측 칼럼이 아니라 2단 아래 전체 폭에 놓인다 — 청약 전에 반드시 보여야 하므로 sticky 칼럼 안에서 스크롤 밖으로 사라질 수 있는 자리에 두지 않는다 (아래 "법적 고지 배치 규칙" 참조).

`[ASSUMPTION]` 판매자·관리자 화면은 지금 PC 폭 기준으로만 만들어져 있다. 같은 앱 안에 있지만 이번 반응형 규칙의 적용 대상이 아니며, 모바일 대응이 필요한지는 확인된 바 없다.

## Interaction Primitives

- **탭으로 실행한다.** 롱프레스는 브라우저 기본(텍스트 선택·이미지 저장)에 남긴다.
- **스와이프 제스처를 만들지 않는다.** 스와이프 삭제 없음 — 삭제는 항상 눈에 보이는 `삭제` 텍스트다. 상품상세 이미지 좌우 스와이프만 예외이며 썸네일 탭으로도 같은 일을 할 수 있어야 한다.
- **pull-to-refresh 없음.** 브라우저 기본 동작에 맡긴다.
- **되돌아가기는 브라우저 뒤로 가기와 항상 일치한다.** 헤더 뒤로가기가 브라우저 히스토리와 어긋나면 안 된다.
- **파괴적 동작은 확인한다.** `삭제`·`주문 취소`는 확인 후 실행. `[ASSUMPTION]` 확인 UI(다이얼로그/시트) 형태 미정.
- **애니메이션은 최소.** 화면 전환 애니메이션·히어로 모션·자동 재생 캐러셀 없음.
- **금지:** 배너 캐러셀, 자동 팝업, 재입고/할인 유도 알림, 무한 스크롤 자동 로드, 스크롤 하이재킹, 카운트다운 타이머.

## Accessibility Floor

동작 기준. 색 대비는 DESIGN.md가 담당한다.

- **터치 타깃 최소 44 × 44px.** `[ASSUMPTION]` 목업의 수량 스테퍼(26px)·`삭제`·`보기` 링크가 이보다 작다 — 시각 크기는 유지하되 히트 영역을 패딩으로 44px까지 넓힌다.
- **색만으로 상태를 전달하지 않는다.** 품절·구매 불가·주문 상태는 **색 + 텍스트 라벨**을 항상 함께 쓴다: 품절 카드는 채도 저하 + `품절` 태그 + 취소선, 구매 불가 묶음은 회색조 + `구매 불가 · 품절` + 안내 문장, 상태 라벨은 색이 달라도 글자가 상태를 말한다.
- **포커스 표시는 반드시 보인다.** `[ASSUMPTION]` 슬러 시스템의 `--color-focus-ring`은 브랜드 파랑 기반이라 구매자 화면에서 쓸 수 없다 — 먹색 계열 포커스 링을 별도 정의해야 한다. `outline: none`은 대체 링과 한 쌍일 때만.
- **키보드로 전체 흐름을 완주할 수 있다.** 포커스 순서는 읽기 순서를 따른다. 하단 고정 바는 DOM 순서상 콘텐츠 뒤에 두어 포커스가 먼저 걸리지 않게 한다.
- **한국어 스크린리더 고려.** `<html lang="ko">`. 브랜드 라벨의 넓은 자간(`.15em`)이 낭독을 방해하지 않도록 자간은 CSS로만 주고 글자 사이에 공백을 넣지 않는다. 금액은 `121,000원`으로 두어 "십이만 천 원"으로 읽히게 하고, 숫자만 남긴 뒤 `원`을 이미지·의사요소로 붙이지 않는다.
- **의미 있는 마크업.** 상태 라벨은 시각적으로 배지가 아니어도 스크린리더에는 상태로 전달돼야 한다. 비활성 옵션 칩은 `aria-disabled` + `품절`이 함께 읽혀야 한다 — 숨기지 않는 이유가 사라지지 않도록.
- **폼 오류는 필드와 연결한다.** 라벨-필드-오류 메시지가 프로그램적으로 묶여야 한다.
- **글자 크기 확대 대응.** 200%까지 확대해도 잘리는 컨트롤이 없어야 한다. 고정 높이 바(54px·56px)는 확대 시 늘어날 수 있어야 한다.
- **동작 줄이기 존중.** `prefers-reduced-motion`에서 전환 효과를 끈다.

## Key Flows

주인공은 **김소연** — 화면 목업에 이름과 주소가 들어 있는 인물이다. 서울 마포에 살고, 인스타그램에서 본 링크로 SLUR에 처음 들어온다.

### Flow 1 — 처음 와서 주문까지 (김소연, 목요일 밤, 침대에서)

1. 링크를 눌러 **상품목록**이 열린다. 로그인하지 않은 상태다. `SLUR` 로고 아래 `이번 주, 손이 자주 가는 것들`. 여섯 품목이 두 열로 어긋나며 흐른다. 브랜드명이 먼저 눈에 들어온다 — `토림도예`, `무연`, `곳간`.
2. `곳간`의 황동 촛대 세트에 `품절` 태그가 붙어 있다. 지워진 게 아니라 그냥 없는 것으로 표시돼 있다.
3. 유광 도자 머그를 탭 → **상품상세**. 사진 다섯 장, `유약이 고르게 앉도록 두 번 굽습니다.`
4. 색상 `살구`, 용량 `240ml`을 고른다. 아래 한 줄에 `선택 · 살구 / 240ml · 구매 가능`.
5. `먹`을 눌러 본다. 용량 축의 `320ml`이 회색으로 죽으며 `품절`이 붙는다. 사라지지 않았으므로 그 조합이 원래 있었다는 걸 안다. 다시 `살구`로 돌아온다.
6. 스크롤을 내리면 **판매자 정보**가 펼쳐진 채 있다 — 토림도예 / 김현수 / 사업자등록번호 / 통신판매업 신고번호 / 마포구 성미산로 주소. 그 아래 `SLUR는 통신판매중개자이며 통신판매의 당사자가 아닙니다.` 파는 사람이 누구인지 알고 나서 버튼을 누른다.
7. `장바구니 담기`. 로그인이 필요하므로 **로그인** 화면이 뜬다. 계정이 없으니 `회원가입`.
8. **회원가입** — 이메일·비밀번호(8자 이상)·이름, 휴대폰번호는 선택. 필수 동의 두 개를 체크한다. `가입하면 구매자로 시작합니다.`
9. 돌아온 자리에서 담기가 이어진다. 탭바 장바구니에 배지가 붙는다. 리넨 테이블보도 담는다.
10. **장바구니** — 판매자별로 묶여 있다. `토림도예` 묶음에 배송비 3,000원, `온실` 묶음은 무료배송. 왜 배송비가 따로 붙는지 묶음이 설명한다. 머그를 2개로 올린다. `주문하기 (2건)`.
11. **주문서** — 배송지를 채우고(`우편번호 검색` → 04044 → 마포구 양화로 45, 301호), 요청사항에 `부재 시 경비실에 맡겨주세요`. 결제 금액 118,000 + 3,000 + 도서산간 0 = **121,000원**. 결제 수단은 무통장입금 하나뿐이고, `입금 확인 후 배송이 시작됩니다. 주문 후 3일 안에 입금하지 않으면 자동 취소됩니다.` 그 아래 다시 중개자 고지. 하단 고정 바에 `121,000원 · 주문하기`.
12. **절정.** 탭하면 **주문완료**가 뜬다. `주문이 접수되었습니다`, 주문번호 `20260721-0037`. 화면의 중심은 축하가 아니라 **입금 안내 상자**다 — 121,000원, 국민은행 123456-01-987654, 예금주 슬러, 기한 2026년 7월 24일까지, 그리고 `입금자명을 주문자 이름(김소연)과 같게 해주세요.` 아직 끝나지 않았고 무엇을 해야 하는지를 화면이 감추지 않는다.
13. `주문 상세 보기` → **주문상세**. 입금 안내가 최상단에 그대로 있고, 두 묶음이 각각 `입금대기`에 `주문 취소` 버튼을 달고 있다.

**실패 경로.** 11단계에서 `주문하기`를 누르는 사이 누군가 마지막 머그를 사 갔다면, 주문은 만들어지지 않고 어떤 항목이 문제인지 알려준다 (FR-35). 12단계는 오지 않는다.

### Flow 2 — 담아둔 물건이 품절됐을 때 (김소연, 다음 주 화요일 점심)

1. 지난주에 담아두고 결제하지 않은 것이 있어 `장바구니` 탭을 연다. 배지에 `3`.
2. **장바구니** — 위에서 두 번째, `곳간` 묶음의 사진이 회색으로 바래 있다. 브랜드명 옆에 `구매 불가 · 품절` 태그, 금액 89,000원에 취소선, 체크박스가 꺼져 있다.
3. **절정.** 묶음 아래 한 줄: `담은 뒤 품절된 상품입니다. 주문에서 제외됩니다.` 그리고 합계를 본다 — 상품 금액 118,000원, 배송비 3,000원, **결제 예정 금액 121,000원**. 89,000원이 이미 빠져 있다. 화면이 조용히 계산을 끝내 두었고, 김소연이 할 일은 결정하는 것뿐이다. 지워지지도, 몰래 결제되지도 않았다.
4. `삭제`를 눌러 곳간 묶음을 치운다. 배지가 `2`로 줄고 합계는 그대로다 — 애초에 포함돼 있지 않았으니까.
5. `주문하기 (2건)` → 주문서 → 주문완료. Flow 1의 11~13단계와 같다.

**분기.** 3단계에서 삭제하지 않고 그대로 `주문하기`를 눌러도 된다. 구매 불가 묶음은 주문서로 넘어가지 않는다. 장바구니에는 남아 있으므로 재입고를 기다리며 놔둘 수 있다 — v1에 재입고 알림은 없다.

### Flow 3 — 배송이 따로 갈 때 (김소연, 금요일 오후)

1. `주문내역` 탭. 세 건이 최신순으로 놓여 있고, 각 행 우측에 상태가 있다 — `입금대기`(액센트), `배송중`(먹색), `배송완료`(흐림). 색의 온도만으로 무엇이 내 차례인지 알 수 있다.
2. 목요일 밤에 주문한 `20260721-0037`을 연다. 입금은 이미 했고 관리자가 확인을 끝냈다.
3. **주문상세.** 입금 안내 상자가 사라져 있다. `토림도예` 묶음은 `배송준비`, `온실` 묶음은 `배송중`이고 송장번호 `CJ대한통운 1234-5678-9012`가 붙어 있다.
4. **절정.** 온실 묶음에는 `주문 취소` 버튼이 없고 `배송준비 이후에는 취소할 수 없습니다.`가 대신 있다. 토림도예 묶음에는 아직 버튼이 있다. **한 주문 안에서 두 묶음의 시간이 따로 흐른다** — 화면은 그것을 하나의 진행바로 뭉개지 않고 있는 그대로 보여준다.
5. 하단 안내: `배송준비 전까지 판매자 묶음 단위로 취소할 수 있습니다.` 버튼이 있는 묶음과 없는 묶음이 왜 나란한지 이 한 줄이 설명한다.
