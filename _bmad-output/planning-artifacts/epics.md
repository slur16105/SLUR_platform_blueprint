# SLUR 커머스 플랫폼 1호 - Epic Breakdown

## Overview

This document provides the complete epic and story breakdown for SLUR 커머스 플랫폼 1호, decomposing the requirements from the PRD, UX Design if it exists, and Architecture requirements into implementable stories.

## Requirements Inventory

### Functional Requirements

FR-1: 이메일+비밀번호 회원가입·로그인 (Argon2id 해시)
FR-2: 카카오 로그인 (구매자 화면·판매자/관리자 화면 공통), FastAPI 자체 JWT 발급, 범용 OAuth 구조
FR-3: 단일 계정 다중 역할(구매자/판매자/관리자), FastAPI RBAC
FR-4: 이메일 가입 최소 수집(이메일·비밀번호·이름·선택 휴대폰), 이메일 인증 생략
FR-5: 입점 신청 폼 — 법정 필수(상호·대표자·사업자번호·통판신고번호·주소·연락처)+브랜드명·소개
FR-6: 신청 페이지 상시 존재, 초청 전용→공개 전환은 운영 정책 변경만으로
FR-7: 관리자 승인/반려(사유 입력), 승인 시 판매자 역할 부여·즉시 등록 가능, "심사 중" 표시
FR-8: 상품 등록(상품명·가격·설명·이미지·옵션), 검수 없음 — 즉시 노출
FR-9: 옵션 축 최대 2개 → 조합 행 자동 생성 → 행별 [옵션값|추가금액|재고|판매상태] 그리드 입력
FR-10: 조합별 수량 재고, 0=자동 품절+수동 토글, 품절 옵션은 "품절" 표기 비활성
FR-11: 재고 차감은 주문 생성 시점 원자적, 취소 시(자동·자유·관리자) 복원
FR-12: 상품 상태 판매중/품절/숨김 3단계, 판매자 전환
FR-13: 상품 이미지 대표 1장+추가(상한 10장), 상세는 텍스트+이미지
FR-14: 판매자 혼합 단일 장바구니 + 단일 주문서
FR-15: 주문 내부는 판매자별 하위 주문 분리, 배송 상태 독립 전이, 구매자에겐 주문 하나로 표시
FR-16: 주문서 — 배송지 입력(카카오 우편번호 검색), 요청사항, 금액 요약(상품+배송비+도서산간)
FR-17: 배송비 판매자 설정(무료/유료+제주·도서산간 추가비), 우편번호 자동 판정
FR-18: 주문 상태 전이 — 입금대기→결제완료→배송준비→배송중→배송완료, 3일 미입금 자동취소, 구매자 자유취소는 판매자 묶음 단위·배송준비 전
FR-19: 상태 전이 규칙 FastAPI 강제 — 미정의 전이는 어떤 클라이언트에서도 불가
FR-20: 구매확정 상태 값만 정의, v1 미사용
FR-21: 배송중 전이 시 택배사+송장번호 입력, 구매자 주문상세 표시 (추적 연동 없음)
FR-22: 주문내역 목록(최신순)·주문상세(판매자별 배송 상태, 배송지, 금액, 입금 계좌)
FR-23: 입금대기 주문에 입금 안내(금액·계좌·기한) 표시, 플랫폼 단일 계좌(설정값)
FR-24: 판매자 대시보드 — 신규 주문·배송준비 중 건수, 품절 임박(재고 5 이하) 상품
FR-25: 판매자 주문관리 — 자기 주문 조회, 배송준비→배송중(송장)→배송완료 처리
FR-26: 판매자 상품관리 — 목록·등록·수정·상태 전환
FR-27: 관리자 입점 관리 — 신청 목록·상세, 승인/반려
FR-28: 관리자 입금 확인 — 입금대기 목록에서 수동 확인→결제완료 전이
FR-29: 관리자 주문 관리 — 전체 조회·검색, 상태 강제 변경+메모
FR-30: 관리자 상품·회원·판매자 조회 (읽기 중심, 제재 없음)
FR-31: 푸터 — 사업자 정보 + 통신판매중개자 고지
FR-32: 상품상세·주문서에서 청약 전 중개자 지위·판매자 신원정보 노출
FR-33: 이용약관·개인정보처리방침 페이지 (오픈 게이트에서 법률 검토)
FR-34: 카테고리 — 운영자 관리 단일 계층, 관리자 생성·수정·순서 변경, 상품당 1개, 목록 필터 탭
FR-35: 장바구니 — 조합 단위 담기(재담기 수량 합산)·수량 변경·삭제, 구매 불가 항목 표시·제외, 주문 생성 시 재검증
FR-36: 홈 편성 — 운영자가 관리자 화면에서 구매자 홈 `/`의 히어로·편성 슬롯을 편성(지면 제목·문장·대표 이미지·노출 상품 묶음·순서·노출 기간), 편성이 없으면 상품목록(서문형)으로 폴백

NFR-3: 재고 차감·상태 전이 동시성 정합성 (DB 수준 원자성)

#### UX-DR 목록 (2026-07-21 추출 — Epic 8 스토리 AC의 근거)

두 스파인에서 뽑은 실행 가능한 요구사항이다. 각 항목은 그대로 AC로 옮길 수 있어야 하며, 수치는 DESIGN.md 프론트매터 토큰이 정본이다. **대상은 구매자 라우트 전용** — 판매자·관리자 화면은 이 목록의 적용 대상이 아니다.

**UX-DR1 — 구매자 팔레트 토큰 신설, 브랜드 파랑 미사용**
구매자 화면 전용 색 토큰을 신설한다: 종이 `#faf8f4` / 종이 그늘 `#f2eee6`, 먹색 `#1f1d1a` + 보조 먹 4단(`#2c2a26`·`#3c3934`·`#4d4942`·`#6a645c`) + 흐린 3단(`#7d7a75`·`#8e8b85`·`#9c968c`), hairline `#e3ded4`, 흙빛 액센트 `#8c4a32` + 저농도 3종(`#f1e5df`·`#faf1ec`·`#ecd9d0`), 폼 계열(`#ffffff`·`#ded8cc`·`#b3ada3`·`#fdf7f4`). 예외 색은 카카오 `#fee500` 하나뿐이다.
**브랜드 파랑 `#2f6bff`(슬러 시스템 `--color-brand-*`)은 구매자 라우트에 나타나지 않는다.** 판매자·관리자 화면의 파랑은 그대로 유지된다 — 색이 갈리는 것은 사고가 아니라 결정이다. 액센트는 링크·선택 상태·가격 강조·경고에만 쓰고 면으로 넓게 깔지 않는다.

**UX-DR2 — 브랜드 라벨 타이포는 이 시스템의 지문**
브랜드명은 상품명보다 **먼저·굵게·자간을 벌려** 놓는다. 기준값 **11px / 800 / 자간 `.15em`**(목록 카드). 문맥 변형은 묶음 헤더 10.5px/`.14em`, 상품상세 11.5px/`.17em`까지만 허용하고 **굵기 800과 넓은 자간은 어디서도 놓지 않는다**. 상품명은 그 아래 13px/400 `#605b53`, 가격은 다시 먹색 800. 브랜드 라벨은 독립 컴포넌트로 만들어 카드·장바구니 묶음·주문서 묶음·주문상세 묶음에서 같은 얼굴로 반복된다.
글꼴은 한 벌(`Pretendard Variable` → `Pretendard` → `Apple SD Gothic Neo` → `Noto Sans KR` → `system-ui`)만 쓰고 명조를 섞지 않는다. 금액은 항상 `121,000원` 형식 + `font-variant-numeric: tabular-nums` (`₩`·소수점·`12.1만` 금지).

**UX-DR3 — 하단 탭바 56px 4탭, ≥768에서 상단 내비로 전환**
< 768: 하단 고정 탭바 **56px**, 4탭 균등 — `홈` · `장바구니`(개수 배지) · `주문내역` · `내 정보`. 배경 종이색, 상단 1px hairline, 아이콘 22px는 CSS 도형 또는 인라인 SVG(아이콘 폰트·이모지·CDN 금지), 라벨 10.5px/600.
**활성 표시는 색 채움이 아니라** 먹색 + 라벨 굵기 800 + 아이콘 선 굵기 1.4px→1.9px. 채워진 알약·밑줄 인디케이터를 두지 않는다.
≥ 768: 탭바를 제거하고 **같은 4개 항목을 헤더 우측 상단 내비**로 옮긴다. 현재 위치는 먹색 + 굵기로만 표시한다(밑줄 없음).
배치 규칙: 탭바는 최상위 4화면(상품목록·장바구니·주문내역·내 정보)에만 둔다 / 하단 고정 CTA가 있는 화면에는 탭바를 두지 않는다 / **장바구니만 예외**로 CTA + 탭바 2단을 허용한다. 탭 전환 시 각 탭의 스크롤 위치를 유지하고, 같은 탭 재탭은 최상단 복귀다.
상단바는 54px 고정이며 세 형태(로고형 / 로고 중앙형 / 뒤로가기+제목형)를 쓴다. **최상위 화면의 제목은 좌측 정렬로 통일**하고, 로고 중앙 헤더는 로그인·주문완료 두 화면에만 쓴다. 로그인·장바구니 헤더에는 뒤로가기를 두지 않는다.

**UX-DR4 — ≥768에서 2단으로 갈라지는 화면은 3개. sticky는 짧은 칼럼에 건다**

> **[2026-07-21 개정]** 최초 추출 시점의 `62/34 · 우측 sticky` 일괄 규칙은 768·1280 렌더 검증에서 결함이 확인되어 폐기됐다. **`DESIGN.md`의 Layout & Spacing → 반응형 절이 정본이다.**

|---|---|---|---|
| 상품상세 | 이미지 갤러리 **50%** | 브랜드·상품명·가격·옵션 축·배송비·CTA 2개 **50%** | **좌(이미지)** |
| 장바구니 | 판매자 묶음 목록 62% | 금액 요약 + `주문하기 (N건)` 34% | 우(요약) |
| 주문서 | 배송지·요청사항·주문 상품·결제 수단 62% | 금액 요약 + `주문하기` 34% | 우(요약) |

**긴 쪽이 흐르고 짧은 쪽이 따라붙는다.** 상품상세만 균등 분할에 좌측이 붙는 이유: 이미지 칼럼은 hero+썸네일로 일찍 끝나는데 정보 칼럼은 훨씬 길다. 62/34로 두면 넓은 칼럼이 먼저 끝나 왼쪽에 200px 구멍이 생기고 좁아진 오른쪽에서 옵션 칩이 꽉 차고 배송비가 접힌다.

≥768에서는 하단 고정 CTA 바가 사라지고 **주 행동 버튼이 sticky 칼럼 안으로 승격**된다 — 화면 밖으로 밀려나면 안 된다. 두 칼럼 길이가 비슷해지면(묶음이 하나뿐일 때 등) sticky를 걸지 않는다.
**끝까지 한 단으로 두는 화면**: 주문내역·주문상세·내 정보·로그인·회원가입(최대 640px), 주문완료(최대 560px). 2단으로 만들지 않는다.
**폭이 바뀌어도 상태는 유지된다** — 창을 넓히거나 기기를 돌려 재배치될 때 선택한 옵션 조합·장바구니 체크 상태·입력 중인 배송지가 초기화되지 않는다.

**UX-DR5 — 본문 최대 폭 1080px, 상품목록 열 수 2/3/3**
| | < 640 | 640~767 | ≥ 768 |
|---|---|---|---|
| 좌우 여백 | 20px | 20px | 32px |
| 본문 최대 폭 | — | — | **1080px** 가운데 정렬 (읽는 화면은 640px) |
| 상품목록 열 | **2열** | **3열** | **3열** (카드가 커진다) |
| 카드 간격 (세로/가로) | 26 / 14px | 26 / 14px | 36 / 20px |
| 카드 이미지 높이 | 160~216px | 160~216px | **200~260px 고정** (`object-fit: cover`) |

**[2026-07-21 개정]** 카드 이미지 높이는 카드 폭을 따라가지 않는다. ≥768에서 카드 폭이 325px까지 커지는데 390px 비율을 유지하면 이미지가 410px을 넘어 노트북 첫 화면에 한 줄의 사진 절반만 들어온다 — 390px보다 밀도가 나빠져 B를 고른 근거를 스스로 부순다. 품목별 높이 차이(리듬)는 고정 범위 안에서 유지한다.

**행 내부 최대 폭 560px.** 라벨-값 행(판매자 정보, 금액 요약)과 항목 조작 행(수량 스테퍼 ↔ `삭제`)은 칼럼이 아무리 넓어도 560px 안에서 좌측 정렬한다. 630px 칼럼에서 `space-between`을 그대로 쓰면 한 상품의 조작이 500px 벌어져 무관한 두 열로 읽힌다.

데스크톱에서 끝까지 펼치지 않는다. 브레이크포인트는 기존 슬러 시스템(sm 640 / md 768 / lg 1024 / xl 1280)을 그대로 물려받는다. 상품 카드 이미지 높이는 품목마다 다르게(160~216px) 두어 열이 어긋나며 흐르게 한다. 별도 모바일 사이트를 만들지 않으며 서버가 기기를 판별해 분기하지 않는다 (AD-14 — 표면은 하나다).

**UX-DR6 — 먹색 포커스 링을 신설한다**
슬러 시스템의 `--color-focus-ring`은 브랜드 파랑 기반이라 **구매자 화면에 쓸 수 없다** (UX-DR1과 충돌). 먹색 계열 포커스 링 토큰을 별도로 정의하고 모든 인터랙티브 요소(버튼·링크·칩·체크박스·입력·탭)에서 **보이는 포커스 표시**를 보장한다. `outline: none`은 대체 링과 한 쌍일 때만 허용한다.
키보드만으로 전체 흐름(목록 → 상세 → 담기 → 주문서 → 주문)을 완주할 수 있어야 하고, 포커스 순서는 읽기 순서를 따른다. **하단 고정 바는 DOM 순서상 콘텐츠 뒤**에 두어 포커스가 먼저 걸리지 않게 한다.

**UX-DR7 — 터치 타깃 최소 44 × 44px**
시각 크기는 목업대로 두되 **히트 영역을 패딩으로 44px까지 넓힌다.** 현재 미달인 것: 수량 스테퍼(26px), 장바구니 `삭제` 텍스트 링크, 주문내역 `보기` 링크, 약한 텍스트 버튼(`로그아웃`). 글자 크기 200% 확대에서도 잘리는 컨트롤이 없어야 하며, 고정 높이 바(54px·56px)는 확대 시 늘어날 수 있어야 한다.

**UX-DR8 — 색만으로 상태를 전달하지 않는다**
품절·구매 불가·주문 상태는 **색 + 텍스트 라벨을 항상 함께** 쓴다.
- 품절 상품 카드: 채도 저하(`saturate(.45)`) + 먹색 `품절` 태그 + 가격 취소선 — **숨기지 않는다.**
- 품절 옵션 조합: 회색 면 + 취소선 + `품절` 서브라벨 — **숨기지 않는다.** `aria-disabled`와 `품절`이 함께 읽혀야 한다.
- 구매 불가 장바구니 묶음: 회색조 + `구매 불가 · 품절` 태그 + 안내 문장.
- 상태 라벨: 면 없는 11.5px/800/`.05em` 글자. 색은 층만 나눈다(입금대기 액센트 / 진행 중 먹색 / 완료·취소 흐린색). **액센트가 붙는 상태는 입금대기 하나뿐**이다. 스크린리더에는 상태로 전달돼야 한다.
성공 초록·위험 빨강을 도입하지 않는다 — `주문 취소` 버튼도 빨강을 쓰지 않는다.

**UX-DR9 — 빈 상태·로딩·오류 표현**
| 상황 | 표현 |
|---|---|
| 장바구니 비어 있음 | `장바구니가 비어 있습니다.` + `쇼핑 계속하기` |
| 주문내역 없음 | `아직 주문이 없습니다.` |
| 카테고리에 상품 없음 | `이 카테고리에는 아직 상품이 없습니다.` |
| 목록 로딩 | 카드 골격(skeleton). **화면 중앙 스피너를 쓰지 않는다.** |
| 목록 끝 | `최근 주문부터 보입니다.` (주문내역) |
| 제출 중 | 버튼 비활성 + 중복 제출 차단. 스피너 없이 텍스트 유지 |
| 폼 오류 | 해당 필드에만 오류 테두리·면 + 아래 한 줄 메시지. **상단 요약 배너를 쓰지 않는다.** 라벨-필드-오류가 프로그램적으로 묶인다 |
| 로그인 실패 | 두 필드 모두 오류 표기 + `이메일 또는 비밀번호가 올바르지 않습니다.` — 어느 쪽이 틀렸는지 말하지 않는다 |
| 네트워크·서버 실패 | 문장형 한국어 메시지 + 재시도 수단. **HTTP 코드·에러 code 문자열을 화면에 노출하지 않는다** (분기는 `code`로, 표시는 `message`로) |

**UX-DR10 — 법적 고지 배치 규칙 (FR-31·32·33) — 옮기거나 접거나 지울 수 없다**
| 자리 | 무엇을 | 규칙 |
|---|---|---|
| **상품상세** — 하단 CTA **위** | 판매자 신원정보 6항목(상호·대표자·사업자등록번호·통신판매업 신고번호·사업장 주소·연락처) + 중개자 고지 | 접이식이되 **기본 펼침**. 청약 버튼(`장바구니 담기`·`바로 구매`)보다 위 |
| **주문서** — `주문하기` 직전 | 중개자 고지 | 스크롤 끝이 아니라 **청약 전에 읽을 수 있는 자리** |
| **내 정보** | 플랫폼 사업자 정보 + 중개자 고지 + 이용약관·개인정보처리방침 링크 | 웹 푸터 대응 |

**≥768 2단 화면에서도 고지는 우측 sticky 칼럼이 아니라 2단 아래 전체 폭**에 놓는다 — 스크롤 밖으로 사라질 수 있는 자리에 두지 않는다. 모달·별도 페이지·"더보기" 뒤에 숨기는 구현은 요건을 만족하지 않는다.
고지 문구는 **글자 그대로** 쓴다(요약·의역 금지): `SLUR는 통신판매중개자이며 통신판매의 당사자가 아닙니다. 상품 정보와 거래에 관한 책임은 판매자에게 있습니다.` 플랫폼 사업자 정보는 현재 placeholder이므로 `임시 정보` 태그와 `실사업자 정보는 서비스 오픈 전에 교체됩니다.`를 함께 보인다.

**UX-DR11 — 라우트와 접근 권한 (공개/보호 경계)**
| 화면 | 라우트 | 로그인 |
|---|---|---|
| 상품목록 (홈) | `/` | **불필요** |
| 상품상세 | `/products/[id]` | **불필요** |
| 장바구니 · 주문서 · 주문완료 | `/cart` · `/checkout` · `/orders/complete` | 필요 |
| 주문내역 · 주문상세 | `/orders` · `/orders/[id]` | 필요 |
| 내 정보 | `/me` | 필요 |
| 로그인 · 회원가입 | `/login` · `/signup` | — |

**`/`는 구매자 상품목록이다** — 지금의 로그인 유도 랜딩이 이 자리를 내준다. 판매자·관리자도 `/`로 들어와 상품을 보고 자기 화면(`/seller`·`/admin`)으로는 헤더·안내를 통해 이동한다 (한 계정이 여러 역할을 가지므로 진입점을 쪼개지 않는다, FR-3).
비로그인은 상품목록·상품상세까지 볼 수 있고 **장바구니에 담는 순간부터 로그인이 필요**하다. 보호된 동작을 시도하면 `/login`으로 보내고 **성공 후 원래 하려던 자리로 돌려보낸다** — 담으려던 조합을 잃어버리면 안 된다.
`[ASSUMPTION]` 비로그인 장바구니는 브라우저에 보관하지 않는다 (서버 장바구니 병합 규칙의 복잡도가 완주에 기여하지 않음).

**UX-DR12 — 깊이는 그림자가 아니라 종이로 만든다**
`box-shadow`를 쓰지 않는다 (슬러 시스템 `--shadow-*` 토큰은 구매자 화면 미사용). 깊이 수단은 셋뿐이다: 8px `#f2eee6` 종이 접기 띠 / 1px hairline / 테두리 상자. 고정 상단바·탭바·CTA 바의 경계도 1px 선으로만 표시한다. 구획 강도는 3단(없음 / 1px hairline / 8px 띠)으로만 나눈다.
라운드 스케일: 2px 태그, 3px 안내 상자·취소 버튼, **4px 기본**(버튼·입력·옵션 칩·사진), 5px 입금 안내 상자, `full`은 카테고리 칩과 개수 배지 **둘에만**. 그라디언트 면·원형 크롭·오버레이를 얹지 않는다.

**UX-DR13 — 판매자 묶음이 구조를 가르친다**
장바구니·주문서·주문상세는 같은 **판매자 묶음 카드** 뼈대를 반복한다: 헤더(브랜드 라벨 + 배송비 또는 상태 라벨) → 상품 행 → 푸터. 묶음 사이는 1px hairline.
장바구니에서는 체크박스·수량 스테퍼·`삭제`를, 주문서에서는 읽기 전용을, 주문상세에서는 **묶음 각자의 상태·배송비·취소 버튼·송장 줄**을 갖는다. **주문 전체에 걸리는 상태 표시나 전체 취소 버튼을 두지 않는다** (FR-15·18).
금액 요약의 행 순서는 고정이다: 상품 금액 · 배송비 · 도서산간 추가 · 합계. **도서산간 추가는 0원이어도 줄을 지우지 않는다.** 합계 값(21px/800 액센트)은 화면당 한 번만 허용한다. 장바구니 탭 배지는 담긴 항목 수 **전체**(구매 불가 포함)를, CTA `(N건)`은 **주문 가능 항목만** 센다 — 두 숫자는 다를 수 있다.

**UX-DR14 — 입금 안내 상자는 v1의 결제 UI다**
무통장입금이 유일한 결제 수단이므로 이것이 주문 이후 가장 중요한 컴포넌트다. 두 변형을 유지한다.
- **주문완료** — 종이 면 + 1.5px 액센트 테두리, 노치 캡션 `입금 안내`, 금액 27px/800 액센트, 계좌·예금주·기한, 입금자명 안내 메모. **이 화면의 중심은 축하가 아니라 이 상자다.**
- **주문상세(입금대기)** — `#faf1ec` 면 + 1px `#ecd9d0` 테두리, 금액 20px, 주문번호 바로 아래 최상단. 입금대기가 아닌 주문의 상세에서는 **사라진다**.

**UX-DR15 — 문구는 조용한 존댓말, 짧은 동사형 버튼**
감탄사·마케팅 과장·이모지 없음. 화면은 재촉하지 않고 사실과 다음 할 일만 말한다. `주문이 접수되었습니다` / `담은 뒤 품절된 상품입니다. 주문에서 제외됩니다.` / `입금 확인 후 배송이 시작됩니다. 주문 후 3일 안에 입금하지 않으면 자동 취소됩니다.` / `배송준비 전까지 판매자 묶음 단위로 취소할 수 있습니다.`
버튼은 `장바구니 담기` `주문하기` `삭제` `주문 취소`. 날짜는 `2026.07.21` 또는 `2026년 7월 21일`. 판매자는 브랜드명으로 부른다(`토림도예`, `온실` — `판매자 A` 금지).

**UX-DR16 — 인터랙션 원칙과 금지 목록**
탭으로 실행하고 롱프레스는 브라우저 기본에 남긴다. **스와이프 제스처를 만들지 않는다**(스와이프 삭제 없음 — 삭제는 항상 보이는 텍스트). 상품상세 이미지 좌우 스와이프만 예외이며 썸네일 탭으로도 같은 일을 할 수 있어야 한다. pull-to-refresh 없음. 헤더 뒤로가기는 **브라우저 히스토리와 항상 일치**한다. `삭제`·`주문 취소` 같은 파괴적 동작은 확인 후 실행한다(`[ASSUMPTION]` 확인 UI 형태 미정).
**모달을 쓰지 않는다** — 우편번호 검색만 예외로 <768 전체 화면 오버레이 / ≥768 가운데 모달이다.
애니메이션은 최소로 두고 `prefers-reduced-motion`에서 전환 효과를 끈다. ≥768에서만 hover를 쓰되 hover에만 있는 정보를 두지 않는다.
**금지**: 배너 캐러셀, 자동 팝업, 재입고·할인 유도 알림, 무한 스크롤 자동 로드, 스크롤 하이재킹, 카운트다운 타이머, 할인율·별점·리뷰 수·`BEST` 리본, 검색·찜·쿠폰(v1 밖).
`<html lang="ko">`를 두고, 브랜드 라벨의 넓은 자간은 CSS로만 준다(글자 사이 공백 삽입 금지 — 낭독을 깨뜨린다). `[ASSUMPTION]` 다크 모드는 v1에 없다 — 구매자 팔레트는 라이트 한 벌만 정의되어 있다.

**Given** 비로그인 상태로 상품상세에서 `장바구니 담기`를 누름
**When** `/login`에서 로그인 성공
**Then** 원래 상품상세로 돌아오고 담으려던 조합·수량이 유지된 채 담기가 이어진다 (UX-DR11)

**Given** 로그아웃
**When** 실행
**Then** 세션 쿠키와 역할 쿠키가 제거되고 `/`로 이동한다

### Story 8.3: 상품목록·상품상세

As a 구매자,
I want 로그인하지 않고도 무엇을 파는지 보고 옵션을 고르는 것,

**Given** `/` 상품목록
**When** 비로그인 상태로 접근

**And** 카테고리는 `GET /api/v1/products/categories` 응답 순서를 그대로 쓴다 — 이름·순서를 하드코딩하지 않는다
**And** 카테고리 선택은 즉시 목록을 갈아끼운다
**And** 카드는 사진 → 브랜드 라벨(11px/800/`.15em`) → 상품명 → 가격 순으로 놓인다 (UX-DR2)

**When** 목록에 표시

**And** 품절 카드도 탭하면 상품상세로 들어간다 (어떤 조합이 남았는지 볼 수 있어야 한다)

**Given** 상품이 없는 카테고리 / 로딩 중
**When** 조회
**Then** `이 카테고리에는 아직 상품이 없습니다.` / 카드 골격(skeleton)이 표시된다 — 화면 중앙 스피너를 쓰지 않는다 (UX-DR9)

**Given** `/products/[id]` 상품상세
**When** 옵션 축(최대 2개)의 한 값을 선택
**Then** 다른 축 칩의 상태가 즉시 갱신되고, 불가능해진 조합의 칩은 회색 면 + 취소선 + `품절` 서브라벨로 **비활성 표기**된다 — 숨기지 않는다 (FR-9·10)
**And** 일부 조합만 품절인 축 값에는 `일부 품절` 서브라벨이 붙는다
**And** 비활성 칩은 `aria-disabled`와 `품절`이 함께 읽힌다 (UX-DR8)

**Given** 두 축이 모두 정해짐
**When** 선택 결과 줄을 확인
**Then** 조합(`살구 / 240ml`)과 상태(`구매 가능` 또는 `품절`)가 한 줄로 표시되고, 조합 목록을 따로 나열하지 않는다

### Story 8.4: 장바구니

**When** `−`·`+`를 누름
**Then** `PATCH /api/v1/carts/items/{id}`로 반영되고 합계가 즉시 갱신된다
**And** 수량 1에서 `−`는 비활성이다 (삭제와 구분한다)
**And** 스테퍼·`삭제`의 히트 영역은 시각 크기와 무관하게 44 × 44px 이상이다 (UX-DR7)

**And** 체크박스가 해제·잠금되고 **합계와 `주문하기 (N건)`에서 제외**된다
**And** `삭제`는 계속 동작한다 — 지워지지도, 몰래 결제되지도 않는다
**And** 구매 불가 판정은 백엔드 응답을 그대로 쓴다 (AD-10 단일 술어 — 클라이언트가 재고를 보고 자체 판단하지 않는다)

**When** 구매 불가 항목이 섞여 있음

**Given** `삭제`
**When** 누름
**Then** 확인 후 실행된다 (`DELETE /api/v1/carts/items/{id}`) — 스와이프 삭제를 만들지 않는다 (UX-DR16)

**Given** 빈 장바구니
**When** 조회
**Then** `장바구니가 비어 있습니다.` + `쇼핑 계속하기`가 표시된다 (UX-DR9)

## Epic 9: 구매자 홈 편성 (Editorial Home)

> **신설** — 구매자 홈 재설계(시안 C · 운영자 편성) 승인의 산물. Epic 8이 구매자 홈 `/`를 상품목록으로 재표면화한 뒤, Epic 9는 그 `/` 자리를 운영자가 직접 편성하는 지면으로 끌어올린다.

지금 구매자 홈 `/`는 카테고리 칩 + 상품 그리드(상품목록)뿐이라 운영자의 큐레이션(플랫폼의 존재 이유)이 홈에 드러나지 않는다. Epic 9는 운영자가 홈의 히어로와 편성 슬롯(지면 제목·문장·대표 이미지·노출 상품 묶음·순서·노출 기간)을 관리자 화면에서 편성하게 하고, 편성이 하나도 없으면 홈이 기존 상품목록(서문형)으로 폴백한다 — 홈이 비어 보이는 순간이 없다.

**FRs covered:** FR-36
**주요 참조:** FR-34(카테고리 — 편성 슬롯의 상품 묶음과 병존) · FR-12(상품 상태 — 숨김·품절 상품의 편성 노출 규칙) · AD-9(ERD·마이그레이션 승인 게이트) · AD-10(구매 가능 단일 술어) · AD-12(파생 값 백엔드 계산) · AD-13(하드코딩 금지) · UX-DR1·2·5·8·9·10·12(구매자 시각 계약) · `DESIGN.md`·`EXPERIENCE.md`

- `[ASSUMPTION]` 히어로도 `home_features`의 한 유형으로 통합할지 별도 단일 레코드로 둘지는 ERD 승인 시 확정한다

### Story 9.2: 관리자 홈 편성 화면

As a 운영자,
I want 관리자 화면에서 홈 지면을 만들고 고치고 순서와 노출 기간을 정하는 것,
So that 코드 배포 없이 홈의 큐레이션을 바꿀 수 있다.

**Acceptance Criteria:**

**Given** 관리자 홈 편성 화면
**When** 지면(히어로·슬롯) 생성·수정·삭제
**Then** 각 지면에 제목·문장·대표 이미지·노출 상품 묶음·순서·노출 기간·활성 토글을 입력·저장하고, 저장 결과가 편성 목록에 그대로 반영된다

**Given** 지면의 상품 묶음 편집
**When** 상품을 검색해 묶음에 추가·제거하고 묶음 내 순서를 바꿈
**Then** 선택한 상품이 `home_feature_items`에 지면 내 순서와 함께 저장된다
**And** 숨김·삭제된 상품은 묶음에 추가할 수 없거나 추가 시 경고가 표시된다 (FR-12)

**Given** 지면 순서 변경과 활성 토글
**When** 순서를 바꾸거나 지면을 비활성화
**Then** 변경이 즉시 저장되고, 비활성 지면은 공개 조회 대상에서 빠진다

**Given** 노출 기간(시작·종료)
**When** 값을 비우거나 채움
**Then** 비우면 상시 노출, 채우면 그 기간에만 공개 조회에 포함된다

**Given** 편성 화면 접근
**When** 판매자 역할·비로그인이 시도
**Then** 403으로 거부된다 — 편성은 관리자 전용이다

**Dev Notes:**
- 참조: FR-36, FR-12, FR-34 / 판매자·관리자 화면 규칙(파랑 팔레트·슬러 시스템)을 따른다 — 구매자 팔레트는 이 화면에 쓰지 않는다
- 상품 검색은 기존 관리자 상품 조회(Story 5.6)의 목록·검색을 재사용한다
- `[ASSUMPTION]` 편성 미리보기(관리자가 저장 전 홈 모습을 확인) 제공 여부는 구현 시 확정한다

### Story 9.3: 공개 편성 조회 API

As a 구매자,
I want 홈을 열면 운영자가 편성한 지면이 한 번에 내려오는 것,
So that 히어로와 편성 슬롯이 빠르게 그려진다.

**Acceptance Criteria:**

**Given** 활성이고 현재 노출 기간에 든 지면들
**When** 공개 편성 조회 API 호출 (`GET /api/v1/home` — 홈 1회 호출)
**Then** 히어로 + 편성 슬롯들이 지면 순서대로, 각 슬롯의 상품 묶음이 묶음 내 순서대로 함께 반환된다 — 홈이 추가 왕복 없이 한 번의 호출로 그려진다

**Given** 편성 슬롯에 묶인 상품
**When** 응답을 구성
**Then** 각 상품의 현재 가격·대표 이미지·구매 가능 여부는 `products` 단일 술어(AD-10)로 판정한 백엔드 값으로 실린다 — 편성 데이터의 복제 값이 아니다 (AD-12)
**And** 품절 상품은 목록에서 빼지 않고 `sold_out` 표식과 함께 반환된다 (숨기지 않음, UX-DR8)
**And** 숨김·삭제된 상품은 응답에서 제외된다 (FR-12)

**Given** 활성 지면이 하나도 없거나 전부 노출 기간 밖
**When** API 호출
**Then** 편성이 비어 있음을 명확히 알리는 응답(빈 편성)을 반환한다 — 홈이 폴백을 판단할 수 있다

**Given** 비로그인 상태
**When** 호출
**Then** 통과한다 — 홈 편성은 공개 라우트다 (상품목록·상품상세와 같은 공개 경계)

**Dev Notes:**
- 참조: FR-36, FR-12, AD-10, AD-12, UX-DR8 / `EXPERIENCE.md` §라우트와 접근 권한(공개 경계)
- 가격·재고·판매상태는 편성 도메인이 아니라 `products` 도메인이 소유한다 — 편성 조회는 조인·재사용만 한다
- `[ASSUMPTION]` 대표 이미지 응답이 사전서명 URL인지 공개 URL인지는 기존 상품 이미지 응답 규약에 맞춰 구현 시 확정한다

### Story 9.4: 구매자 홈 재설계 (편성 지면·서문형 폴백)

As a 구매자,
I want 홈에서 운영자가 고른 이야기와 상품을 먼저 보는 것,
So that 무엇을 파는 곳인지 한눈에 느끼고 자연스럽게 둘러볼 수 있다.

**Acceptance Criteria:**

**Given** 활성 편성이 있는 `/`
**When** 접근 (비로그인 포함)
**Then** 분할 히어로(제목·문장·대표 이미지)와 편성 슬롯들이 조회 API(9.3) 순서대로 렌더되고, 각 슬롯 아래에 그 묶음의 상품 카드가 표시된다 (UX-DR2·5·12)
**And** 슬롯의 품절 상품 카드는 숨기지 않고 채도 저하 + `품절` 태그 + 가격 취소선으로 표기된다 (`sold_out`, UX-DR8)
**And** 상품 카드를 누르면 상품상세(`/products/[id]`)로 들어간다

**Given** 활성 편성이 하나도 없는 `/`
**When** 접근
**Then** 홈이 서문형 상품목록(카테고리 칩 + 상품 그리드, Story 8.3)으로 폴백한다 — 빈 히어로나 빈 화면을 보여주지 않는다

**Given** 전 구매자 화면
**When** 렌더
**Then** 홈을 포함한 구매자 화면 하단에 푸터(사업자 정보 + 중개자 고지 + 정책 링크, `임시 정보` 태그 포함)가 놓인다 (FR-31·33, UX-DR10) — 상시 푸터가 없던 자리를 메운다

**Given** 홈 → 상품상세 → 뒤로
**When** 브라우저 뒤로가기로 홈에 복귀
**Then** 홈의 스크롤 위치가 복원되어 보던 슬롯 자리로 돌아온다 — 맨 위로 튀지 않는다 (UX-DR16, 브라우저 히스토리 일치)

**Given** 로딩 중 / 폭 변화
**When** 홈을 렌더
**Then** 상품 그리드는 카드 골격(skeleton)으로 채우고 화면 중앙 스피너를 쓰지 않으며 (UX-DR9), 좌우 여백·본문 최대 폭·상품 열 수는 8.1의 반응형 규칙(2/3/3열, 1080px)을 따른다 (UX-DR5)

- 참조: FR-36, FR-31, FR-33, AD-12, UX-DR2·5·8·9·10·12·16 / `DESIGN.md`·`EXPERIENCE.md`
- 폴백 판정은 9.3 응답의 "빈 편성" 신호로 한다 — 클라이언트가 편성 유무를 자체 계산하지 않는다
- API: `GET /api/v1/home`(신규, 9.3) · 폴백 시 기존 상품목록 API(`GET /api/v1/products/categories`·`GET /api/v1/products`) 재사용
