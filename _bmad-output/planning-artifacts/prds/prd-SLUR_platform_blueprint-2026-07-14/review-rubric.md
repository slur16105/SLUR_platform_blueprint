# PRD Quality Review — SLUR 커머스 플랫폼 1호

> 검증 기준: `prd-validation-checklist.md` 7개 차원. 스케일 보정: 1인 운영자 + 초청 판매자 5~10팀의 실서비스 완주 프로젝트. 독자는 Slur와 다운스트림 AI(아키텍처/ERD/구현). 엔터프라이즈 잣대가 아니라 이 스케일 기준으로 판정했다.

## Overall verdict

이 PRD는 규모에 맞는 형태(케이퍼빌리티 스펙)로 쓰였고, 결정을 결정으로 말하며, 기각한 대안과 이유를 부록에 남긴 드물게 정직한 문서다. 전략 축("완주가 1차 목표" + counter-metric)이 실제로 범위 결정을 지배한 흔적이 §2와 §4 전반에서 확인된다. 남은 위험은 다운스트림이 가장 세게 기대는 done-ness 쪽에 있다 — 장바구니 자체의 동작 FR이 비어 있고, 취소 시 재고 복원이 미기술이며, 용어집이 없어 ERD 설계 시 명사 해석을 AI가 추정하게 된다. 이 세 가지를 메우면 아키텍처/ERD 단계로 넘기기에 충분하다.

## Decision-readiness — strong

결정이 "고려사항"으로 숨지 않는다. FR-14 "판매자별 장바구니 분리는 명시 기각 (구매자 이탈 UX — Slur 직접 경험)", FR-8 "검수 단계 없음 — 등록 즉시 노출 (초청제가 품질 게이트)", FR-34 "(계층 구조·판매자 자율 분류는 기각)"처럼 무엇을 버렸는지가 채택 근거와 함께 적혀 있다. 부록의 "기각된 대안과 이유" 표는 배송비 무료 기각 사유를 "입점 협상 카드를 시스템이 선점하는 꼴"이라고 트레이드오프의 실체까지 말한다. §2의 counter-metric은 장식이 아니라 "실제로 이 기준으로 네이버 로그인·제재 기능·상품 검수를 v1에서 제외했다"는 적용 실적을 인용한다.

열린 질문 중 OQ-1은 진짜 열려 있다(판매자 협상에서 검증할 사업 질문, 시스템 영향 없음까지 명시). OQ-2는 질문 안에 답(`[ASSUMPTION]` v1은 상수)이 들어 있어 사실상 닫힌 질문이지만, 답을 붙여 닫은 것을 투명하게 보여주므로 감점 사유는 아니다.

## Substance over theater — strong

페르소나 시어터 없음 — §3은 역할 3개 표 하나로 끝나고, 각 역할이 실제 FR 그룹(F5/F6/F7)을 지배한다. NFR도 보일러플레이트가 아니다: NFR-1은 이 프로젝트 고유의 아키텍처 스탠스(권한·비즈니스 로직 FastAPI 단일 소유, Supabase Auth/RLS 미사용)이고, NFR-3은 "재고 차감·상태 전이는 동시 요청에도 정합성" 이라는 제품 특정 요구다. NFR-4가 "별도 수치 목표를 두지 않는다"고 선언한 것은 이 스케일에서 성능 시어터를 만드는 것보다 정직한 선택이다. 비전 시어터도 없음 — §1 한 문단이 곧 제품 정의다.

## Strategic coherence — strong

테제가 명확하다: 큐레이션 초청제 편집숍 + "1차 목표는 완주, 2차 목표는 블루프린트 추출"(§2). 이 테제가 범위를 실제로 지배한다 — 초청제가 품질 게이트라는 논리가 검수 제외(FR-8)·관리자 화면 최소화(F7 운영 원칙)·입점 폼 축소(FR-5)까지 일관되게 관통한다. §8 "v1 완성 ≠ 오픈" 게이트 구분은 무통장입금 v1이라는 위험한 경계를 규제 근거(에스크로·지급대행, 부록)와 함께 안전하게 봉인한 좋은 설계다.

### Findings
- **low** 2차 목표(블루프린트 추출)의 판정 조건 부재 (§2) — "이 PRD와 파생 산출물이 다음 플랫폼의 시작 문서가 된다"는 방향 선언이지 완료 조건이 아니다. 완주 후 회고 시점에 흐릿해질 수 있음. *Fix:* v1 완주 시점에 "블루프린트로 추출할 산출물 목록"을 확정한다는 한 줄을 §8 게이트나 OQ에 추가.

## Done-ness clarity — adequate

강한 부분: FR-18 상태 전이 다이어그램(자동취소 기한·자유취소 경계 포함), FR-19 "정의되지 않은 전이는 어떤 클라이언트에서도 불가능해야 한다", FR-11 "동시 주문에도 음수 재고가 발생하지 않아야 한다"는 그대로 테스트 케이스가 된다. FR-9의 옵션 그리드(축 최대 2개 → 조합 자동 생성 → 행별 4개 필드)도 구현 가능 수준.

그러나 다운스트림이 가장 기댈 차원인 만큼 구멍이 세 개 보인다.

### Findings
- **high** 장바구니 동작 FR 부재 (§4 화면 목록엔 "장바구니"가 있으나 §5에는 FR-14의 "단일 장바구니" 구조 선언뿐) — 담기/수량 변경/삭제, 담긴 상품이 품절·숨김·삭제됐을 때의 표시와 주문서 진입 시 처리, 옵션(조합) 단위로 담는지 여부가 모두 미기술. FR-11이 "장바구니 담기 시점 차감은 하지 않는다"고 했으므로 '담긴 후 품절' 경로는 반드시 발생하는데 처리가 없다. ERD(장바구니 테이블 형상)와 구현이 전부 추정에 의존하게 됨. *Fix:* F4에 장바구니 FR 1~2개 추가 — 조합 단위 담기, 수량 변경·삭제, 주문 생성 시점 재고·판매상태 재검증과 실패 시 동작.
- **high** 취소 시 재고 복원 미기술 (FR-18) — 3일 미입금 자동취소와 구매자 자유취소가 모두 정의되어 있으나, 취소된 주문의 차감분(FR-11에서 주문 생성 시 차감)이 재고로 복원되는지 어디에도 없다. 복원 없이는 취소가 누적될수록 재고가 유령 소진됨. *Fix:* FR-18 또는 FR-11에 "취소(자동·자유·관리자 강제) 시 해당 조합 재고 복원" 한 줄 추가. 관리자 강제 변경(FR-29)에 의한 취소도 포함 여부 명시.
- **medium** FR-24 "품절 임박(재고 N 이하)"의 N 미정 — `[ASSUMPTION]` 태그가 붙은 항목이긴 하나 N이 상수인지 판매자 설정인지도 없다. *Fix:* "N=5 상수, v1은 코드 수정으로 조정" 수준으로 고정 (OQ-2와 같은 방식).
- **low** FR-16 "우편번호 검색"의 수단 미지정 — 도서산간 판정(FR-17, 부록의 판정 테이블)과 연결되는 입력인데 검색 제공자(예: 카카오 우편번호 서비스)는 아키텍처 몫으로 남아 있음. 스케일상 허용 범위. *Fix:* 아키텍처 단계에서 결정한다는 위임 표시만 있어도 충분.

## Scope honesty — strong

§4 "v1 제외" 목록이 명시적이고, "금지가 아니라 필요 미확인"이라는 재진입 규칙까지 붙어 있다. `[ASSUMPTION]` 태그 12개가 실제 추정 지점(FR-4 수집 항목, FR-23 플랫폼 단일 계좌, FR-33 법률 검토 유보 등)에 정확히 붙어 있고, §8 오픈 게이트는 "v1 완성"과 "실서비스 오픈" 사이의 침묵하기 쉬운 간극을 4개 항목으로 명문화했다. 부록의 기각 대안 표는 조용한 디스코프가 아니라 이유 있는 디스코프임을 증명한다. `[NOTE FOR PM]` 콜아웃은 없으나 독자가 곧 PM(Slur)인 이 구조에서는 OQ 섹션이 그 역할을 대신하고 있어 결격이 아니다. 열린 항목 밀도(OQ 2 + ASSUMPTION 12)는 이 스테이크에서 건강한 수준.

## Downstream usability — adequate

이 PRD는 체인 최상단(아키텍처→ERD→스토리로 흐름)이므로 이 차원이 중요하다. FR ID는 FR-1~34로 유일하고, 교차 참조("F2 참조", "F3 참조", `research-*.md`, `.memlog.md`)는 전부 실재 파일·섹션으로 해소됨을 확인했다. 부록이 "아키텍처 문서로 갈 것"을 명시 분리해둔 것도 다운스트림 추출을 쉽게 한다.

### Findings
- **medium** 용어집(Glossary) 부재 — "조합"(variant), "하위 주문", "역할", "판매상태" vs "상품 상태"(FR-9의 행별 판매상태와 FR-12의 상품 3단계 상태는 서로 다른 개념인데 이름이 비슷함) 같은 도메인 명사가 정의 없이 쓰인다. 본문 내 사용은 일관적이지만, ERD 명명 시점에 AI가 각 명사의 경계(예: 조합별 판매상태와 상품 상태의 관계 — 상품이 '판매중'인데 전 조합이 수동 품절이면?)를 추정하게 된다. *Fix:* 6~8개 항목의 미니 용어집 추가 — 특히 "상품 상태(3단계)"와 "조합별 판매상태"의 관계 한 줄 정의.
- **low** FR-34가 F3 블록 안에서 FR-13 다음에 등장 (§5 F3) — OQ-3 확정분을 추가하며 번호를 뒤에 붙인 것으로 이력상 자연스럽고 ID 자체는 유일하므로 실해는 없음. 재정렬은 불필요하나, 이후 FR 추가도 같은 방식(말미 번호 부여, 재번호 금지)을 유지할 것.

## Shape fit — strong

정확한 형태 선택이다. 1인 운영자 + 소수 초청 판매자 프로젝트에 UJ·페르소나 서사 없이 역할 표 + 케이퍼빌리티 스펙으로 간 것, 성공 기준을 사용자 지표가 아닌 운영자 판정 기준(완주 기여 여부)으로 둔 것 모두 루브릭의 "solo → capability spec" 권고와 일치한다. 근거·기각 대안·벤치마킹 수치를 addendum으로 분리해 본문을 154줄로 유지한 구조도 "독자는 Slur와 AI"라는 선언(§ 머리말)에 부합한다. 과형식화·과소형식화 모두 없음.
