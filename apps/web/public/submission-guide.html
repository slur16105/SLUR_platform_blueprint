판매자·운영자가 함께 완주하는 큐레이션 커머스

SLUR Platform Blueprint는 운영자가 판매자를 선별·초청하는 디자인 편집숍 모델을 바탕으로, 입점부터 상품·장바구니·주문·운영 처리까지의 실제 서비스 흐름을 구현한 프로젝트입니다.

FastAPI · Next.js · PostgreSQL 현재 데모 열기 ↗ GitHub 저장소 보기 ↗
!
외부 데모는 Hub맥의 Docker 기반 로컬 검증 환경입니다.

운영 Supabase 데이터와 분리된 Postgres 및 로컬 데모 카탈로그를 사용합니다. URL은 임시 터널이므로 Hub맥과 Docker가 실행 중인 동안에만 접속할 수 있습니다.

01 · FEATURES

역할별로 끊기지 않는 커머스 흐름

한 계정이 구매자·판매자·관리자 역할을 가질 수 있으며, 권한과 상태 전이는 FastAPI에서 일관되게 판단합니다.

구매자

탐색, 장바구니, 주문

카테고리와 상품을 탐색하고, 옵션·재고를 확인한 뒤 장바구니와 주문 흐름을 진행합니다. 무통장입금 확인 기반의 주문·배송·취소 상태를 제공합니다.

흐름
상품 탐색 → 장바구니 → 주문 미리보기 → 주문 생성 → 주문내역·취소

판매자

입점 신청부터 재고·배송 관리

판매자 신청과 관리자 승인을 거쳐 판매자 프로필을 만들고, 상품·옵션 조합·재고·배송비를 관리합니다. 주문을 확인해 배송·배송완료 상태로 전이합니다.

흐름
입점 신청 → 승인 → 상품 등록 → 재고 관리 → 주문 처리

관리자

승인, 카탈로그, 주문 운영

판매자 입점 신청을 심사하고, 카테고리와 운영 설정을 관리합니다. 입금 확인, 주문 상태 변경, 취소·환불 처리 및 회원·판매자 조회를 제공합니다.

흐름
입점 심사 → 카테고리 운영 → 입금 확인 → 주문·취소 관리

02 · ARCHITECTURE

FastAPI를 유일한 권한 판단 지점으로 둔 구조

프런트엔드는 화면과 BFF를 담당하고, 인증·권한·상태 전이·주문 규칙은 서버 API가 소유합니다.

Next.js 웹구매자 · 판매자 · 관리자
역할별 화면 및 BFF
FastAPI인증 · RBAC · 주문 상태 전이
도메인 규칙의 단일 소유자
PostgreSQL / Storage로컬 검증 DB 분리
운영 전환 대상

분리 원칙: Supabase는 향후 매니지드 PostgreSQL과 Storage 대상으로만 두며, Supabase Auth·RLS·Edge Functions에 비즈니스 규칙을 분산하지 않습니다.

  • 역할 쿠키는 화면 라우팅 힌트일 뿐, 권한 상승 근거가 아닙니다.
  • 실제 접근 권한은 FastAPI의 JWT claim과 역할 의존성에서 다시 판정합니다.
  • 로컬 시더도 공개·관리·판매자 API를 호출해 실제 권한과 도메인 규칙을 통과합니다.

03 · SECURITY

인증 정보와 상태 변경을 경계별로 방어

아래 내용은 현재 구현의 보안 설계입니다. 실사용자 외부 판매는 별도의 오픈 게이트를 완료하기 전까지 허용하지 않습니다.

비밀번호와 로그인 실패

비밀번호는 Argon2id로 해시합니다. 존재하지 않는 계정도 더미 해시 검증을 수행하고, 이메일 부재와 비밀번호 불일치를 같은 401 응답으로 처리해 계정 존재·타이밍 노출을 줄입니다.

JWT와 세션 회전

Access JWT는 issuer·subject·만료 시간을 검증하며 기본 수명은 30분입니다. Refresh token은 원문이 아닌 SHA-256 해시를 저장하고, 조건부 갱신으로 1회 사용 후 회전·폐기됩니다.

역할 기반 접근 제어

JWT의 역할 claim을 FastAPI require_role 의존성이 판독합니다. 프런트의 역할 힌트가 변조되더라도 서버의 실제 권한 판정을 우회할 수 없습니다.

상태 변경 요청 방어

웹 BFF의 상태 변경 POST·PUT 요청은 same-origin을 확인합니다. 인증 BFF에는 캐시 금지 헤더를 적용하고, 로그아웃은 refresh 쿠키 경로를 모두 소거하도록 검증합니다.

카카오 계정 연결 정책

카카오는 신원 확인에만 사용하고 토큰은 FastAPI가 발급합니다. 기존 이메일 계정과의 자동 연결을 금지해 계정 선점·탈취 위험을 막으며, 콜백 URI는 서버 allowlist로도 확인합니다.

환경변수와 데이터 경계

JWT_SECRET과 DB 연결은 환경변수로만 주입합니다. 현재 Docker 데모 DB는 운영 데이터와 분리되어 있으며, 로컬 시더는 ENVIRONMENT=local 및 Docker Postgres에서만 실행됩니다.
