# checks — 의존성 0 자동 단언 (프로토타입)

> 액션 A-E8-4. **채택 판단용 프로토타입이다.** 테스트 스위트가 아니다.
> 논증은 하나다 — *"Epic 8에서 실제로 난 버그 6개 중 5개는, 이 다섯 명제를 그때 갖고 있었다면 잡혔다."*

## 무엇을 설치했나 — 아무것도

Node 22 내장만 쓴다: `node:test` · `node:assert` · 내장 TypeScript 타입 스트리핑 · `node:http`.
`package.json`의 `dependencies`·`devDependencies`는 **한 줄도 바뀌지 않았다**. 추가된 것은 `scripts`의 `check` 한 줄뿐이다.

```bash
npm run check          # 전부
npm run check -- unit  # 순수 단언만 (서버 없음)
npm run check -- http  # 실제로 나가는 응답만 (npm run build 선행 필요)
```

## 다섯 명제 — 전부 Epic 8에서 실제로 난 버그다

| # | 명제 | 원래 버그 | 위치 |
|---|---|---|---|
| 1 | `clearSessionCookies`가 refresh 쿠키를 `/api`·`/api/auth` **두 path 모두** 소거한다 | `ResponseCookies`가 이름으로만 키를 잡아 `Set-Cookie`가 한 줄만 나갔다 → 로그아웃 후 세션 부활 | `unit/session-cookies.check.mjs` |
| 2 | `formatPhone`이 서울(02)을 두 자리로 끊는다 | `0212345678` → `021-234-5678` | `unit/phone-format.check.mjs` |
| 3 | 인증 BFF 응답에 `Cache-Control: no-store`가 있다 (공개 BFF 대조군) | 인증 경로만 헤더가 비어 PII 캐시 가능 | `http/cache-control.check.mjs` |
| 4 | 상태 변경 BFF가 위조 Origin에 403 봉투를 준다 (정상 Origin은 통과) | Origin 검사 부재 → 크로스사이트 POST | `http/origin-guard.check.mjs` |
| 5 | 주문서에서 중개자 고지가 `주문하기`보다 **먼저** 만들어진다 (두 폭 모두) | ≥768에서 고지가 CTA 아래 → 규제 요건(FR-32) 위반 | `http/broker-notice-order.check.mjs` |

6번째 버그(`overflow-x: hidden`이 앱 전체 sticky를 죽임)는 **이 방식으로 잡히지 않는다.** 아래 「잡히지 않는 것」에 실측 근거를 적었다.

## 구조 — 서버가 필요한가로 가른다

```
checks/
  run.mjs               러너. unit → http 순서로 돌리고 실행 시간을 찍는다
  resolve-hooks.mjs     Node가 "next/server"·"@/…"를 풀게 하는 해석 규칙 2줄
  unit/                 순수 함수. 서버 없음. 앱 코드를 사본 없이 그대로 import 한다
  http/                 실제로 나가는 응답. 상류 스텁 + next start 필요
    stub-upstream.mjs   FastAPI 자리에 앉는 최소 서버 (닿으면 200)
    server.mjs          next start 기동/정지 · 빈 포트 확보 · 준비 대기
```

`unit/`은 앱 코드를 **복사하지 않고** 그대로 부른다. 사본은 반드시 원본과 갈라지기 때문이다.
그 대가가 `resolve-hooks.mjs` 15줄이다 — 의존성 0은 배관 0이 아니다.

`http/`가 진짜 FastAPI 대신 스텁을 쓰는 이유: 진짜를 띄우면 DB·마이그레이션·시드가 딸려 오고
그 순간 이 검사는 "의존성 0"도 "1.5초"도 아니게 된다. **대신 상류 계약은 검증하지 못한다**(아래 참조).

## 실행 시간 — 실측 (M-series macOS, 3회 반복, 편차 ±10ms)

| 묶음 | 시간 | 내역 |
|---|---|---|
| `unit` (명제 1·2, 단언 6개) | **약 0.26초** | 대부분 Node 프로세스 기동. 단언 자체는 1ms 미만 |
| `http` (명제 3·4·5, 단언 7개) | **약 1.52초** | `next start` 기동·준비 대기 1.11초 + 단언 0.41초 |
| 합계 | **약 1.8초** | |
| (선행) `npm run build` | **약 12초** | `http` 묶음이 요구한다. 빌드가 이미 있으면 0초 |

즉 **커밋 전 훅에 넣을 수 있는 것은 `unit`(0.26초)뿐이다.** `http`는 빌드가 이미 있는 CI 자리다.

## 각 명제가 진짜로 버그를 잡는가 — 되돌림 실험 (5/5 확인)

각 명제마다 코드를 그때의 버그 상태로 되돌려 **단언이 실패하는 것**을 확인하고 원복했다.
실패를 못 보이는 명제는 가짜 단언이다. **다섯 개 모두 실패를 보였다.**

| # | 되돌린 내용 | 결과 |
|---|---|---|
| 1 | `expireCookie` → `res.cookies.set()` 3회 | ❌ `refresh 소거 Set-Cookie가 1줄이다 — 두 path 모두 필요하다` |
| 2 | `head = digits.startsWith("02") ? 2 : 3` → `head = 3` | ❌ `expected '02-1234-5678' / actual '021-234-5678'` (+ 7자리 케이스도 동시 실패) |
| 3 | `noStore()`를 pass-through로 | ❌ `Cache-Control이 아예 없다 — PII 응답이 캐시 가능하다` |
| 4 | `/api/carts/items`에서 `assertSameOrigin` 두 줄 삭제 | ❌ `200 !== 403` (위조 Origin·`null` Origin 둘 다) |
| 5 | `i_legal m_side`를 `i_cta_side` **뒤로** 이동 | ❌ `고지가 주문하기 뒤에 있다 — 고지를 읽지 않고 주문이 끝난다 (FR-32)` |

실험 3의 부수 소득: **Next는 라우트 핸들러 응답에 `Cache-Control`을 스스로 붙이지 않는다.**
붙였다면 명제 3은 코드를 지워도 통과하는 가짜 단언이었을 것이다 — 실험 없이는 알 수 없었다.

## 잡히는 것

- **순수 변환 함수의 출력 문자열** — 포맷·파싱·계산. 가장 싸고 가장 안 깨진다.
- **나가는 HTTP 응답의 성질** — 상태 코드, 헤더(캐시·`Vary`·`Set-Cookie` 줄 수), 오류 봉투 모양.
  `tsc`는 "헤더를 붙였는가"를 절대 모른다. 이 부류가 Epic 8 버그의 다수였다.
- **양방향 가드** — 명제 4는 "막는다"와 "정상 요청은 통과한다"를 함께 단언한다.
  막는 것만 단언하면 *전부 403* 이라는 더 나쁜 회귀를 통과시킨다.
- **산출물의 노드 생성 순서** — 명제 5. JSX 자식 배열 순서는 컴파일·압축을 지나도 보존된다.

## 잡히지 않는 것 (중요)

### 1. `overflow-x: hidden`이 sticky를 죽이는 부류 — 실측으로 확인했다

`app/styles/slur/global.css`의 `body`에 `overflow-x: hidden`을 넣고 빌드한 뒤 전체를 돌렸다.
**13개 단언 전부 통과했다.** 앱 전체의 sticky가 죽은 채로.

선언 하나하나는 유효하고, 결과는 *조합*에서만 나타나며, 보려면 **스크롤해야** 한다.
잡으려면 필요한 것: 실제 브라우저 엔진 + 뷰포트 지정 + 스크롤 조작 후 `getBoundingClientRect` 비교
(Playwright·Puppeteer 급). 즉 **의존성 추가 + CI 브라우저 바이너리**다. 의존성 0의 천장이 여기다.

값싼 절반의 대안: CSS 소스에 대한 **금지 규칙 문자열 검사**(전역 선택자에 `overflow-x: hidden` 금지).
알려진 함정 한 종류는 막지만 "선언은 맞는데 조합이 틀린" 부류 일반은 못 잡는다.

### 2. 화면에 보이는 순서 (명제 5의 한계)

명제 5는 **DOM 생성 순서**를 본다. CSS(`order`·`flex-direction: column-reverse`·`position: absolute`·
`grid-area`)는 DOM 순서를 뒤집을 수 있다. 그러면 규제 요건은 깨지는데 명제 5는 통과한다.
같은 이유로 미디어 쿼리 경계(768px)가 맞는지도 보지 못한다 — 두 사본이 *존재*하고 순서가 맞다는 것까지다.

또 실측 기록: **`/checkout`의 SSR HTML에는 `주문하기`도 `중개`도 없다.** 구매자 표면이 클라이언트
렌더라 서버가 내주는 것은 스켈레톤뿐이다(`x-nextjs-cache: HIT`). 그래서 명제 5는 HTML이 아니라
**브라우저가 내려받는 청크**를 본다. 이게 서버 없이 가능한 최선이었다.

### 3. 상류 계약

`http/`는 스텁을 상대한다. FastAPI의 응답 스키마가 바뀌어도 스텁이 그대로면 **전부 통과한다.**
계약 검증은 `apps/api`의 pytest 소관이고, 이 검사는 **BFF가 무엇을 얹고 무엇을 막는가**만 본다.
그 경계를 흐리면 스텁이 거짓말을 하기 시작한다.

### 4. 그 밖

상태 전이·권한(FastAPI 소관), 클릭 흐름, 문구, 접근성, 성능, 하이드레이션 불일치.

## 유지 비용 — 화면이 바뀌면 몇 개가 깨지나

| # | 화면 변경 취약도 | 무엇에 결합돼 있나 |
|---|---|---|
| 1 | **없음** | 함수 시그니처와 쿠키 이름 상수뿐. 화면과 무관 |
| 2 | **없음** | 순수 함수. 깨진다면 표시 규칙 자체를 바꾼 것 = 의도된 실패 |
| 3 | 낮음 | 라우트 경로(`/api/auth/me`·`/api/products`). 화면 변경엔 둔감 |
| 4 | 낮음~중간 | 대표 라우트 경로 + 요청 본문 모양 + 스텁의 라우트 표 (두 곳을 같이 고쳐야 한다) |
| 5 | **높음** | 클래스 문자열 4개(`i_legal m_side`·`i_cta_side`·`i_legal m_flow`·`b_cta_bar`) + 청크 분할 방식 + 빌드 산출물 |

**5개 중 화면 변경에 취약한 것은 1개(명제 5)다.** 대신 명제 5는 유일하게 규제 요건을 지킨다 —
비싸지만 값이 있다. 표식을 못 찾으면 조용히 통과하지 않고 *"표식을 못 찾았다"*로 **실패**하게 해 두었다
(가짜 통과가 가짜 단언보다 나쁘다).

전체 유지 비용 감각: **5개 중 3개는 사실상 유지 비용 0**, 1개는 API 경로를 바꿀 때 같이 고치는 수준,
1개는 주문서 마크업을 손볼 때마다 확인이 필요하다. 총 코드 약 300줄.

## 채택했을 때의 규약 제안

**언제 돌리나**
- `npm run check -- unit` (0.26초) — 커밋 전. 사람이 손으로 돌리든 훅으로 걸든 부담이 없다.
- `npm run check` (빌드 후 +1.8초) — CI에서 `build` 다음. `build`가 없으면 `http`는 이유를 말하고 멈춘다.
- 배포 게이트로 승격하는 것은 명제가 10개를 넘고 6개월 이상 위양성 0을 유지한 뒤에 논한다.

**누가 추가하나**
- **회귀를 겪은 사람이, 그 수정과 같은 커밋에서 1개.** 그게 유일한 추가 사유다.
  "커버리지를 올리려고" 추가하지 않는다 — 그 순간 이건 프레임워크가 되고, 우리는 프레임워크를 들이지 않기로 했다.
- 새 명제는 **되돌림 실험을 한 번 통과해야 커밋된다.** 실패를 못 보인 단언은 가짜다.
  커밋 메시지나 파일 주석에 "무엇을 되돌려 실패를 봤는지" 한 줄 남긴다.

**무엇을 단언 대상으로 삼나**
- 순수 변환 함수의 **출력 문자열**
- 나가는 HTTP 응답의 **상태·헤더·오류 봉투 모양**
- **보안·규제 불변식** (세션 소거, Origin 가드, 고지 위치, 캐시 금지)

**무엇을 삼지 않나**
- 시각적 결과·레이아웃·반응형 전환 → 브라우저가 필요하다. 사람 눈으로 본다.
- 상류(FastAPI) 계약 → `apps/api` pytest
- 화면 문구·클릭 흐름·해피패스 → 회귀가 실제로 난 적이 없으면 추가하지 않는다
- 커버리지 수치 일반

**상한**
명제 수에 상한을 둔다(예: 20개). 상한에 닿으면 늘리기 전에 *"이제 도구를 들일 때인가"*를 다시 묻는다.
이 프로토타입의 값어치는 규모가 아니라 **설치한 것이 없다는 사실**에 있다.
